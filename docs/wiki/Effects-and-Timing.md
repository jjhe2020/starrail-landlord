## 一次转动的完整顺序

只有准备阶段 `ready` 可以转动；其他阶段调用不会推进状态。合法动作先复制输入状态，再按下表结算；不会原地改写旧状态。

| 顺序 | 阶段 | 具体行为和边界 |
| --- | --- | --- |
| 1 | 开始 | 本关转动 `round+1`、剩余次数 `-1`、累计转动 `+1`，清空本次伤害／效果／威力记录 |
| 2 | 首领的回合阈值 | 用当前回合和现有首领生命检查阶段；回合阈值新加的条款从本次就生效 |
| 3 | 起始护盾衰减 | 有护盾滞纳金则已有盾变为 `R(Q×0.8)`；尚未抽棋盘，当前新技能盾还未生成 |
| 4 | 抽取棋盘 | 对完整编队无放回抽最多 20 人，再随机放入 20 格 |
| 5 | 污染登场 | 被标记实例真的抽中时，先直接扣 6 生命并设定本轮全队攻击折价；若扣至 0，立即失败，后面治疗不会发生 |
| 6 | 缓存羁绊与初始计数 | 取得当前活跃羁绊列表，记录转动前存活敌人数，建立本次临时效果上下文 |
| 7 | 委派 | 按格子索引处理委派主持：先补充见习的生成队列，再尝试完成符合周期的相邻委派；被委派者标记消耗 |
| 8 | 逐格登场 | 从索引 0 到 19；跳过空格和已消耗者。实例登场次数 `ticks+1`，依内容顺序执行登场效果。治疗、盾、成长、资源等立即落地；威力效果排队 |
| 9 | 临时寿命 | 每名已上场且未被消耗的临时角色剩余登场次数 `-1`。到 0 标记 `expired` 并计入本次退场，仍参加本轮后续攻击 |
| 10 | 退场触发 | 若退场计数大于 0，执行 `retire` 效果；计数含委派、临时消耗和本轮自然到期 |
| 11 | 转动触发 | 执行 `spin`、默认攻击前阶段的效果 |
| 12 | 固定奇物分支 | 异木果实每轮治疗；虫网按退场给信用点和治疗；依次判定大乐透、混沌云芝，再给信仰债券信用点 |
| 13 | 持有被动 | 执行 `passive` 中可进入本轮的效果；威力平加／倍率继续入队 |
| 14 | 威力基础 | 为全部未消耗实例构建基础威力、攻击成长、委派奖励和固定平加 |
| 15 | 临时威力队列 | 按入队顺序应用平加，并累计倍率；增幅者的倍率池按受体封顶 ×2.2 |
| 16 | 最终威力 | 加入奇物、精华、敌方威力条款、超频及中列禁锢等倍率，逐格舍入；写入威力记录，消耗待用超频 |
| 17 | 普通攻击 | 按格子索引逐个攻击，每次重新找存活敌人。普通击破在当场执行 `kill` 效果 |
| 18 | 攻击后登场效果 | 再从索引 0 到 19，对未消耗实例执行 `appearance + afterAttacks`，通常为角色追加伤害 |
| 19 | 攻击前排队的追加 | 执行早先由默认攻击前 `appearance`／`spin`／`retire` 等排入的伤害队列 |
| 20 | 攻击后转动效果 | 执行 `spin + afterAttacks`，包括部分羁绊追击／按实际治疗减反击等 |
| 21 | 敌方反击 | 汇总仍存活敌人攻击及周期加伤；先平减、再乘减、再用护盾和生命承担 |
| 22 | 反击后效果 | 只有列车生命仍高于 0 才执行 `retaliation + afterRetaliation`；例如存护羁绊按实际抵盾量追加 |
| 23 | 清理实例 | 从编队删除被消耗及自然到期实例，再加入本轮生成队列；更新退场、伤害和信用点累计 |
| 24 | 精华进度 | 列车还活着才结算精华；先统一观察完整转动，再发放各阈值奖励；完成后再检查一次首领阶段 |
| 25 | 胜负与奖励 | 生命耗尽或未清场而期限已到则失败；否则清场过关，未清场则进入一次招募；第 12 关胜利与后续无尽见[流程](Run-Flow) |

`R(x)=Math.round(x×100)/100`。本表中的“生成”不是立刻上场；生成角色直到第 23 步才进入编队。

### 最容易混淆的三个时点

**登场次数与本关回合不同。** “每第 3 次登场”查该实例 `ticks`；没抽中不增加，换关不清零。“每第 3 次转动”通常查本关 `round`，换关从 0 重新开始。只有真正开始下一次转动才变成第 1 次。

**角色技能条件按到达该条效果时检查。** 例如玲可先治疗，再检查“生命不高于 60%”的护盾条件：`59/100` 先恢复到 `63/100`，该条护盾就不会触发；`50/100` 先恢复到 `54/100`，仍会触发。不是整轮开头为所有技能统一拍一个血线快照。

**攻击前成立和攻击后成立不是一回事。** 素裳的“剩余不多于两列”威力条件在其登场阶段检查，本轮之前还活着的五列不会因为稍后普通攻击清掉三列就补触发。攻击后流风羁绊的残局检查，则可看到本轮普通攻击后的实际剩余数。

## 不同事件怎样取得来源

每次调用效果处理器时，来源总体顺序为：**角色来源 → 持有奇物的顺序 → 已触发精华的持有顺序 → 当前活跃羁绊的定义顺序**。一个来源内部按该条目 `effects` 数组顺序执行。

| 事件 | 角色来源 | 其他来源 |
| --- | --- | --- |
| `appearance` 登场 | 当前处理的一个实例 | 奇物、已触发精华、活跃羁绊 |
| `spin` / `passive` / `retire` | 棋盘全部未消耗实例，按索引 | 奇物、已触发精华、活跃羁绊 |
| `kill` 普通击破 | 造成这次普通击破的实例 | 奇物、已触发精华、活跃羁绊 |
| `merge` 合成 | 刚合成的新实例 | 奇物、已触发精华、按合成后的编队重新计算的活跃羁绊 |
| `floor` 入关 | 编队内非临时实例 | 奇物、已触发精华、该关活跃羁绊 |
| `retaliation` 反击后 | 不自动遍历棋盘角色 | 奇物、已触发精华、活跃羁绊 |
| `acquire` 取得 | 无通用角色巡检 | **只有刚获得或刚达标的那个指定来源** |

没有声明该事件效果的来源不会产生行为。`scope:members` 的羁绊效果，在没有指定作用实例时，会逐个展开为棋盘上符合该羁绊身份的未消耗成员；有指定实例（例如普通击破）时只对该实例检查成员身份。展开出的效果仍要满足自己的额外过滤器与条件。

入关处理会在奖励全部领取／跳过、楼层加一后进行：重置回合和期限、生成敌人、清除上层条款、建立新条款和污染，再跑入关效果，随后发放常规新关免费重掷／偶数关移除、存护火漆及精华的自然赠盾（仍接受自然护盾倍率与条款）。新关逻辑不是一次转动，不发放“每次转动”收益。

## 数据效果的解释顺序

数据中的 `duration` 和 `stacking` 帮助展示时效与叠加意图；实际改变哪个状态、怎样叠加、何时清空由**效果类型和引擎执行入口**确定。不能仅把所有标 `run` 的数值都写成永久成长，也不能把 `multiplicative` 当成无条件、无限制相乘。

### 资格与概率

1. 跳过标记 `legacy:true` 的数据声明及未知类型。旧奇物／精华的这些声明由固定分支实现，不再执行一次。
2. 检查 `condition` 与 `conditions` 中全部条件。
3. 检查 `every` 周期：`appearance` 用实例已增加后的 `ticks`，其他事件用本关 `round`；计数必须大于 0 且整除周期。
4. 检查是否已经用过相同 `oncePerSpin` 键。
5. 若声明 `chance`，从局内种子随机流抽一个数，随机值 `< chance` 才成功。
6. 成功后记录 `oncePerSpin` 键，再执行或排队。

失败的概率检定不会占用一次性键。一次性键含来源类型、来源 ID、来源实例 UID、效果 ID／效果序号；成员展开效果再含受体 UID。因此不同同名实例不会共享同一个技能使用次数。一次转动结束就丢弃这些键，下次重新建立。

条件比较默认 `≥`，还支持 `≤`、`<`、`>`、`=` 和正整数计数整除。整除条件要求值大于 0，所以计数 0 不算“第 3 次”的触发。

### 共用指标字典

相同指标在不同阶段可能有不同值；它们读取当前状态，而不是一张预先冻结的整轮快照。

| 指标 | 取值 |
| --- | --- |
| `hpRatio` / `missingHp` | 当前生命 ÷ 生命上限；`max(0,上限−当前生命)` |
| `shield` / `coins` | 当前公共护盾／信用点余额 |
| `ticks` / `stars` / `growth` | 当前作用实例的登场次数／星级／成长；无实例分别回退为 0／1／0 |
| `round` / `floor` | 本关转动次数／当前关数 |
| `neighbors` / `row` / `column` / `aligned` | 指定空间内满足过滤器的其他未消耗实例数 |
| `edge` / `corner` | 位于相应位置则 1，否则 0 |
| `emptyNeighbors` | 合法相邻范围内的空格和已消耗格数 |
| `present` / `presentDistinct` / `roster` | 未消耗登场实例数／其角色身份去重数／完整编队实例数；均接受自己的过滤器 |
| `enemies` / `emptyColumns` | 当前存活敌人数／`5−当前存活敌人数` |
| `synergies` | 本次上下文的活跃羁绊数量，不是各羁绊的成员人数 |
| `retirements` | 本次上下文已汇总的退场数 |
| `damage` / `healing` | 本次记录中已发生的实际伤害／实际恢复生命 |
| `blocked` / `hpLost` | 当前反击阶段已记下的实际护盾抵挡／生命损失；反击前为 0 |
| `sourcePower` | 当前作用格在本轮威力数组中的值；构建前为 0 |
| `kills` | 过程中为已触发普通击破计数，整轮精华结算前改为全部实际击破数 |

其他未单独处理的指标从本次 `metrics` 取值，无该字段时为 0。空间指标和公开标签含义详见[棋盘与目标](Board-and-Targeting)。累计消费类精华另外观察重掷、移除、已消费信用点、合成的累计计数与取得时基线，见[精华](Essences)。

### 一条数值效果怎样计算

```text
amount = value（未给合法数值则为 0）
若有 per：
    count = 按 per.metric 与 per.filter 取当前指标
    若 divisor > 0：count /= divisor
    仅当 floor:true：count = floor(count)
    若有 cap：count = min(count, cap)
    amount *= max(0, count)
若 scaleWithStars：
    默认 amount *= 实际星级倍率
    有 starFactors 时替换为自定义星级表，并保留星级审计折价
若 scaleWithSourcePower：amount *= 当前来源威力
若 scaleWithTraining 且 type != growth：
    普通数值乘职能培养倍率 T
    指定倍率类使用 max(0.05, 1 + (amount - 1) × T)
再套角色技能条款修正，或羁绊进攻来源缩放
最后由具体类型入口应用增幅职能、治疗／护盾倍率、上限等
```

`per` 的封顶限制的是**除数与可选取整之后的份数**，不是最终量。例如 `value=0.35, metric=missingHp, divisor=10, cap=5`，缺 5 生命时为 `0.175`，缺 60 时为 `1.75`；没有 `floor:true` 就不会要求缺满 10 才给第一份。能力描述中的“每 10 点”不自动隐含向下取整。

`scaleWithStars` 和 `scaleWithTraining` 都是逐条声明；技能没有该标记就不接受该种放大。乘区效果的培养放大偏离 1 的部分，不直接乘整个倍率，详见[成长与升星](Growth-and-Stars)。

羁绊进攻效果统一使用：

```text
X =（持有香涎干酪 ? 1.5 : 1）×（羁绊征收存在 ? 0.75 : 1）
power / damage 数值：amount *= X
powerMultiplier：amount = 1 + (amount - 1) × X
```

该缩放不放大羁绊治疗、护盾、减反击或信用点，不直接改变全队基础威力。

### 排队与重算

- `power` 和 `powerMultiplier` 在触发时先确认资格、周期与概率，再排入威力队列。真正应用时重新计算数值与目标，因此可以读到最终退场计数和已更新成长；**不会重新抽概率或重新检查所有入队条件**。
- 默认攻击前触发的一般 `damage` 延后执行，防止追加先抢在普通攻击前；普通击破和反击后伤害不进入此队列。
- 伤害使用 `sourcePower`、`scaleWithSourcePower` 或 `strongest` 时，执行命中前会用当前最终威力重算数值；普通固定数值保留其排队时算出的量。
- 易伤在触发时就记录匹配受体 UID；本次后续命中查该列表，不会因为另一个实例后来变成更强就自动改给它。
- 若来源随后被消耗，其尚未应用的角色威力／伤害队列会跳过；已发生的治疗、盾、资源与成长不会倒退撤销。

## 效果类型与保存位置

| 类型 | 规则结果 | 时效 |
| --- | --- | --- |
| `power` | 加到本次目标威力数组 | 本轮重算，不写成长 |
| `powerMultiplier` | 进入本次目标倍率数组；增幅者有 ×2.2 池 | 本轮重算 |
| `vulnerability` | 记录匹配攻击者 UID 与额外伤害比例；合计最多 75% | 本轮 |
| `damage` | 按目标规则扣敌人生命 | 即时；生命损失保留 |
| `heal` / `healOverflowShield` | 恢复公共生命；后者可把溢出再转自然盾 | 资源变化保留 |
| `shield` | 增加公共护盾，受容量限制 | 资源变化保留 |
| `growth` | 加到目标永久实例成长，临时受体不会写入 | 本局，合成求和继承 |
| `resource` | 信用点／重掷／移除机会；信用点保留两位，次数向下取整 | 资源变化保留 |
| `retaliationFlat` | 累加本轮反击平减 | 本轮 |
| `retaliationMultiplier` | 相乘本轮反击乘数 | 本轮 |
| `ignoreArmor` | 置本次无视装甲开关，适用后续普通与追加 | 本轮 |
| `summon` | 创建临时角色加入生成队列，寿命夹在 1–3 次实际登场 | 下轮起参与抽取 |
| `consume` | 选符合限制的相邻临时者，标记消耗；成功才加退场并排入来源本次威力奖励 | 实例永久离队，威力只本轮 |
| `selfDamage` | 直接扣生命，默认最低留 1；条目可明确允许致死 | 即时 |
| `maxHp` | 增加生命上限，**不自动同时治疗** | 本局 |
| `extraSpin` | `max(0,floor(amount))` 同时增加剩余转动和本关期限 | 本关 |
| `healMultiplier` / `shieldMultiplier` / `buffMultiplier` / `growthMultiplier` | 在对应入口逐源相乘，不改变已经结算过的历史值 | 条件与来源仍有效时 |
| `rarityMultiplier` | 调整奖励稀有度权重 | 抽该组候选时 |
| `essenceProgressMultiplier` | 调整精华此次获得进度 | 本次进度计算 |

资源入口不允许通过一个泛用字段任意增加未知状态；`resource` 只接受信用点、重掷和移除三类。永久成长的实际受体限制、委派保护和临时寿命见[成长](Growth-and-Stars)与[委派](Assignments)。

## 同一轮中的资源和阈值

资源是共享实时状态。前一格的治疗可以让后一格失去低血线技能条件；前一格的护盾可以让后一格达到护盾门槛。奇物在第 12 步给出的信用点，能被第 13 步才判定的持有被动看到。

退场计数在普通攻击前就包括本轮将自然到期的临时角色；这让“每名本轮退场增加威力”的队列能在这些临时角色最后一次仍会攻击时成立。`expired` 角色没有被视为消耗，仍在本轮技能与目标里；最后才真正移除。

精华的阈值观察发生在全部战斗和退场之后。它们先统一算完本轮进度，再发达标奖励；A 精华本次刚发的信用点不会再喂给 B 精华的同一次进度，刚触发的进度倍率也不回溯放大这一轮。威力精华在攻击后达标，故其威力效果从下一次转动起生效。生命已经归 0 则跳过精华，不能靠同轮丰饶精华救回。

## 记录与复原的界线

当前规则从可信内容定义读取效果，`lastSpin.effects`、威力分解和命中记录只供查看。打开说明、保存、读档不会重放取得奖励、成长或治疗；手改展示快照也不会生成一个真实技能来源。

整轮 `lastSpin` 至多保留 2,000 条展示效果；效果日志缺项不反向改变引擎结算。`inspectSpin` 的独立命中账本可区分 `attack`／`effect` 和角色／奇物／羁绊来源，不能只看 `cell` 把全局伤害算给某张牌。详细存档边界见[存档](Saves-and-Offline)。
