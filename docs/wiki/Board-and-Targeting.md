## 编队、棋盘和实例

**编队**是本局拥有的全部实例；**棋盘**是本次转动实际抽中的实例和位置。技能写“相邻”“同行”“同列”“登场”时，通常查本轮棋盘；[羁绊人数](Synergies)则按整个永久编队的不同角色身份计算，二者不能互换。

每个实例有独立 `uid`、角色 `id`、星级、永久成长和登场次数。同名的两个角色可以同时出现，分别使用自己的成长、次数和位置；技能按人数计数时一般分别算 2 人，按“不同角色身份”时才把同名合并成 1。

每次转动：

1. 对完整编队做一次种子驱动的洗牌。
2. 取前 `min(20, 编队人数)` 个实例，不放回。
3. 对 20 个格子的位置再洗牌一次，将选中实例依序放入。
4. 其余格子为空；上次位置不保留。

临时援军和见习委派也参与抽取，占用同样的上场格。新生成角色在本次结算结束才加入编队，不能插进已经完成抽取的本轮棋盘。普通编队上限 200，具体招募／生成限制见[流程](Run-Flow)和[委派](Assignments)。

### 上场与相邻的概率

在随机位置均匀这一抽样模型下，编队人数 `N`、本轮抽取 `k=min(20,N)` 时：

```text
某一指定实例上场概率 = k / N
两个指定不同实例同时上场概率 = k(k-1) / (N(N-1))  // N >= 2
```

这是抽样几率，不是单次种子流程的预言。20 人以内都上场，但不会填满棋盘；两个人的小队仍分散放在 20 个格子中，不能保证相邻。

已经知道一个实例上场时，另一个指定伙伴与它形成空间关系的概率为：

| 关系 | `N ≤ 20` | `N > 20` |
| --- | --- | --- |
| 相邻 | `5.5 / 19 ≈ 28.95%` | `5.5 / (N-1)` |
| 同行 | `4 / 19 ≈ 21.05%` | `4 / (N-1)` |
| 同列 | `3 / 19 ≈ 15.79%` | `3 / (N-1)` |
| 同行或同列 | `7 / 19 ≈ 36.84%` | `7 / (N-1)` |

这里的同列、同行均指**另一个**实例。相邻格平均数 5.5 来自全棋盘总计 110 条有向相邻位置关系，`110/20=5.5`。完整配队的“至少一个匹配者”概率需要无放回组合计算；不能把多个伙伴的概率直接相加并当成最终概率。

## 坐标与执行方向

玩家界面称第 1 至第 5 列；算法内部列号为 0 至 4。格子索引按从左至右、从上至下排列：

```text
              玩家可见列号
              1   2   3   4   5
内部列号       0   1   2   3   4
上排索引       0   1   2   3   4
第二排         5   6   7   8   9
第三排        10  11  12  13  14
下排          15  16  17  18  19

row(i) = floor(i / 5)
col(i) = i % 5
```

登场处理、普通攻击等需要逐格执行的阶段按索引 `0 → 19` 遍历。上排并非前排坦克线：敌人合并反击公共列车生命，不按行对位攻击角色。行主要服务于技能空间条件；列还决定普通攻击寻敌。

## 空间范围

| 术语／字段 | 几何定义 | 其他格子最多数量 |
| --- | --- | --- |
| 自身 `self` | 相同实例所在格 | 0 |
| 相邻 `adjacent` / 计数 `neighbors` | 行差不超过 1、列差不超过 1，排除自己；包含斜角 | 角落 3、其他边缘 5、内部 8 |
| 同行 `row` | 行号相同 | 4 |
| 同列 `column` | 列号相同 | 3 |
| 同行或同列 `aligned` | 二者的并集，交叉处不重复算 | 7 |
| 边缘 `edge` | 最上排、最下排、最左列或最右列 | 共 14 格 |
| 角落 `corner` | 索引 0、4、15、19 | 共 4 格 |
| 相邻空位 `emptyNeighbors` | 合法相邻格中为空或已被消耗的格子 | 角落最多 3，内部最多 8 |

“相邻”包括斜角，**不跨边界绕行**。索引 4 的相邻格为 `[3,8,9]`；索引 5 在下一排最左侧，并非索引 4 的邻居。棋盘外的位置不算空位：角落不会把棋盘外 5 个方向补成额外空格。

以索引 6 为例：

```text
相邻 = [0,1,2,5,7,10,11,12]
同行其他格 = [5,7,8,9]
同列其他格 = [1,11,16]
同行或同列其他格 = [1,5,7,8,9,11,16]
```

计数指标 `row` / `column` / `aligned` 无条件排除自己；选目标使用同名空间范围时默认可包含自己，然后由 `excludeSelf`、职能或其他标签过滤。相邻范围本身已经排除自己。具体角色的条目决定是否可能选到自身，不能仅凭“同列”二字推定。

## 公开标签与逻辑条件

过滤器从当前内容定义读取角色属性；存档实例里额外塞入一个命途或阵营不会改变身份。

| 条件 | 解释 |
| --- | --- |
| `path`、`element`、`faction`、`attack`、`role` | 对应命途、属性、阵营、攻击形状、主职完全相等 |
| `pathNot` 等 `Not` 项 | 排除相应标签 |
| `id` / `ids` | 某一个／若干角色 ID |
| `starsMin` / `starsMax` | 星级的包含边界上下限 |
| `temporary` | 是否临时角色；最后一次登场已标 `expired` 的角色仍算临时 |
| `commission` | 是否带见习委派标记 |
| `excludeSelf` | 排除与来源相同的实例 UID，不排除所有同名角色 |
| `anyOf` | 子条件之间“或”；与外层其他条件仍为“且” |

例如：

```text
role: attack
anyOf: [{ element: 雷 }, { path: 巡猎 }]
```

意思是“攻击职能，并且是雷属性或巡猎命途”。雷属性支援者不能受益；同时满足雷与巡猎的攻击者只算一个受体／一份人数。一个条件有多个字段时必须全部满足；`condition` 与 `conditions` 数组也必须全部满足。

内部“套路”测试标签不是公开能力标签，过滤器遇到旧 `group` 或 `groupsAny` 条件直接不匹配；没有额外套路技能权限、受益名单或成型奖励。

### 登场、身份、编队的区别

| 指标 | 算什么 |
| --- | --- |
| `present` | 棋盘上实际存在且未被消耗的匹配实例个数 |
| `presentDistinct` | 上述匹配实例按角色 ID 去重后的身份数 |
| `roster` | 完整编队中的匹配实例数；不是去重身份数 |
| 羁绊人数 | 整个编队的永久、非见习委派身份去重计数 |
| `enemies` | 当前存活敌人的数量 |
| `emptyColumns` | `5 - 当前存活敌人数`，即没有存活敌人的敌方列数 |

`roster` 的过滤在需要时写 `temporary:false`；它不会默认排除临时角色。见习委派没有临时寿命，因此若条款要求同时排除见习，必须另有 `commission:false`。被标记消耗的格子会退出登场与邻居计数，并可成为相邻空位；本轮尚未真正清理出编队的实例仍可能出现在直接查 `roster` 的指标中。

## 选取己方受体的精确步骤

一般数据效果依下列顺序选取：

```text
1. 候选 = 所有非空、未被消耗的棋盘格，按索引升序
2. 限定 target 指定的 self / adjacent / row / column / aligned 范围
   未写 target：有作用实例时默认 self，否则默认 team
3. 若另写 range，再与该空间范围取交集
4. 按 filter 去掉不合标签的实例
5. 若 target=strongest 或 selection=strongest：
   默认排除来源 UID（includeSource:true 才保留）
   按“此时威力”降序，平手索引升序
6. target=strongest 只取第一个；targetLimit 再截断到规定人数
```

`matching`、`team` 等未单独指定几何的目标，会在候选棋盘范围内按标签选取；角色条目大多另用邻接或行列限制。`targetLimit:2` 未指定 strongest 时，取索引最小的两个匹配者，**不是随机抽两个，也不是成长最低两个**。

### “最强”的时点

“最强”是效果执行当时选取的结果，不是预先指定的核心，也不是根据出牌顺序或稀有度判断。

```text
比较威力(i) = powers[i]（非零时）
否则 = 基础威力 × 标准星级倍率(1/3/9)
       +（攻击职能 ? 实例成长 : 0）
平手：索引较小者优先
```

- **登场时立即发放的培养**：还未构建本次威力数组，使用上述回退值。它不预知稍后奇物倍率、攻击者条件倍率或易伤；星级税也不改变此回退的标准 1/3/9。
- **稍后应用的威力增益**：此时已有基础威力，且前面队列应用过的平加可以影响排序；储存在另一数组、尚未统一乘上的倍率不会先改变排序。
- **攻击后最强受体追加**：本轮最终威力已经确定，使用最终 `powers` 选择。

例如停云在相邻的两名匹配攻击者间选最强，远处威力更高者始终不在候选范围。受体 A 基础威力高于 B，但 B 稍后将得到更大的倍率，仍不能保证停云会提前选择 B。易伤本身也不加入威力排序。

## 普通攻击寻敌

敌人每列最多一名；存活条件是 `hp > 0`。

```text
origin = 来源格索引 % 5
候选敌人依以下键升序排列：
    (abs(敌人列 - origin), 敌人列)
主目标 = 排序后的第一个
```

因此本列有活敌人时先打本列；本列为空则找最近列；左右距离相同优先**左侧**。没有存活敌人时，该次攻击不命中任何目标。

每名角色出手时重新寻敌。前一名已经清掉的敌人不会继续吸收后一名的普通攻击。单次扩散先确定实际主目标列，再打主目标及其左右紧邻列；主目标被该次攻击击破也不会把余下扩散重新居中。

例：攻击者在第 3 列，敌人只剩第 1、5 列，则优先第 1 列；扩散的副目标只检查第 1 列相邻的第 2 列，不会越过空的第 2、3、4 列打第 5 列。

群攻遍历本次仍存活的全部敌人；每个敌人一次。它的目标规则不受来源列限制。普通攻击各形状倍率见[战斗公式](Combat#普通攻击)。

## 伤害效果的目标语义

伤害效果复用 `target` 字段，但会从受体语义转换为**敌方命中**：

- `team` / `all`：对所有候选存活敌人分别命中。
- `strongest`：先按己方筛选器挑最强作用实例，再从其所在列寻敌。这个实例也提供 `sourcePower`。
- 一般 `self` 等：沿作用实例所在列，寻找最近存活敌人；不是对角色自己造成友军伤害。
- 没有作用格时，从内部中列 2 寻敌。全局伤害记录可能使用 `cell:0`，不能据此认定它由左上格角色发出。
- `excludeOriginColumn:true`：先把来源格对应的敌列从候选中剔除，再按距离和平手左侧规则寻敌。所谓跨列电弧不等于任意连锁跳跃。

同一 `damage` 条目中按邻居人数给出 `a × 人数 × 来源威力`，通常合并成**一个伤害数值／每目标一次命中**，不会自动拆成邻居人数次命中；装甲也相应按实际命中次数扣除。应按条目结构区分“伤害系数随人数提高”和“另一次效果调用”。
