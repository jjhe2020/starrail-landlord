# AI 自动对局与资源难度实验

当前只测试十二关战斗；交租模式已移除，不参与测试、训练或后续数值维护。AI 使用与页面代打相同的纯规则引擎和资源规划器，实验另建独立状态，不修改玩家存档。旧版数据在本文后半部作为历史记录保留，不代表当前规则的胜率。

## 当前验收口径

用户确认四类资源：重掷、移除、信用点消费、生命与护盾合并的防御。完整 AI 在 D10 的目标为约 95%，允许 90%–98%；少有效利用一类的名义档位为 D8，少两类、三类、四类依次为 D6、D4、D2。不同资源的收益可能不同，必须实测，不能因按钮关闭就宣布符合档位定义。

重掷、移除和消费对照禁止对应真实动作。关闭信用点消费也禁止付费重掷，但不禁止使用免费重掷。防御开关仅关闭 AI 的防御价值规划与主动维修/补盾，保留角色自然治疗、护盾、抵伤和正常承伤。关闭规划仍可能实际有效使用防御，因此不能直接当成缺防御对照。敌人生命、伤害与条款候选池不因资源开关改变；难度只依据玩家选择的档位提高敌人生命。

防御的实际使用按用户指定的 **消耗总量 / 生成总量** 测量：

- 生命生成 = 开局生命 + 实际治疗回补；生命消耗 = 实际损失生命，包括角色生命代价和污染。
- 护盾生成 = 开局护盾 + 实际获得护盾；护盾消耗 = 实际抵挡伤害。自然衰减另记为浪费，不计入有效抵伤。
- 合计比例 = （生命消耗 + 护盾抵伤）/（生命生成 + 护盾生成）。批次按总量计算，不平均逐局比例；同时显示两类的独立比例。
- 当前观察分类暂设低于 20% 为偏低，至少 50% 为有效，中间为一般。这些是可调整的报告阈值，不是用户规定的永久数值，也不参与 AI 评分。AI 不会为提高使用率故意受伤。

正式报告保存每组胜率、Wilson 95% 区间、失败关卡、未完成数、实际资源动作与防御总量。是否符合资源难度映射必须结合真实使用；未验证的目标明确保留为未满足。

## 复现与独立样本

奖励与跳过按页面同一推荐的完整浮点概率随机抽样，不强制选择最高分。转动、重掷、移除和补给调用同一 recommendAction；均匀基线仅均匀接受现有奖励，不规划其他动作，用于历史对照，不能将胜率差全部归因于奖励推荐。

所有资源组使用成对初始游戏种子和独立策略随机流。策略不同会改变后续引擎随机数消耗，因此同种子并不意味着后续每张奖励一致。AI 不读取真实未来 rngState；反事实棋盘、未知重掷奖励使用来自公开局面的独立种子。每局运行到十二关胜利或失败，动作上限触发另记未完成。

校准种子用于选择共享生命倍率和难度梯度；正式发布用从未参与调参的种子，各组 1,000 局。规则或算法改变后需要新的发布种子。报告记录规则参数、算法版本、策略配置与前瞻设置，不能在新代码上把旧报告当作已复现。

```powershell
# 当前档位的 AI 与均匀基线，每策略 1,000 局
npm run balance -- --difficulty 10 --runs 1000 --target-min 0.9 --target-max 0.98 --seed fresh-release
# 20 组矩阵，每组 1,000 局；9 组主要对照可加 --scope primary
node scripts/resource-balance.mjs --runs 1000 --workers 8 --seed fresh-resource-release --output docs/benchmarks/resource-balance-latest.json
# 同一资源约束下训练，独立验证失败就保留原配置
npm run train:ai -- --difficulty 10 --runs 100 --generations 2 --candidates 4 --holdout 200 --seed fresh-training
```

普通命令支持 --disable rerolls,removals,credits,defense、--profile、--output。资源矩阵的 --rules 只用于开发校准，正式发布应直接使用锁定的源码参数；--require-target 在目标未满足时保存真实报告并返回非零状态。--fast 关闭前瞻，只用于诊断，不能代替部署策略验收。网页实验每组可选择 30/100/300/1,000 局，关闭面板保留后台任务，取消实验终止 Worker。

## 策略持续优化

优先修复可复现的错误决策，再运行新的校准。训练搜索权重和温度，采用分开的训练、验证和保留种子；最终候选只有在保留集目标提高、胜率和平均通过关数均不降低时才替换策略。运行更多训练并不保证更强，拒绝退化候选也是有效结果。胜率描述特定策略与种子集，不证明全部角色、奇物和构筑都已平衡。
