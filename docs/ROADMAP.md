# 脑暴与迭代计划

本文作为持续追加的设计记录。更新时间：2026-10-12。未来想法可以互相矛盾，新增时先保留原意，再决定替换、实验或合并；不要悄悄改掉最初需求。

## 用户原始需求

> 先初始化 git 之后提交到 GitHub 上面。
>
> 我想做一个幸运房东 like 的游戏，因为本体很简单，我希望你先抄一套完整功能，在 web 实现并适配移动端，然后做美术和文案包装替换，换成星穹铁道的角色 = Symbols，星穹铁道的奇物 = Items 和 Essences，跑通后魔改规则。
>
> 以下为脑暴内容，可能互相矛盾，后续也会添加更多脑暴内容：
>
> 把当前单一的获取金币改为战斗；原本获取 1 金币变成对敌人造成 1 点伤害。
>
> 敌人分 5 列刷新，boss 固定在中间列。
>
> 攻击分为单体（3 × 标准倍率，只能打对应列怪，如果为空则打最近列）、扩散（2 × 标准倍率，只能打对应列怪，如果为空则打最近列，对周围 2 列怪 1 × 标准倍率）、群体（1 × 标准倍率打群体）。
>
> 把房东的规则改造成敌人的技能；增加敌人的美术表现。
>
> 增加自走棋效果，满足词条的不同符号（已经换成星铁角色）凑够数量有额外效果，相同角色可以 3 合 1 成为 2 星级角色。

## 分阶段执行

### 阶段 A：完整可玩的构筑循环

目标是跑通一局，而非只有转轮演示。需要符号池、稀有度、随机转轮、邻接互动、三选一、跳过、重掷、移除、永久道具、条件精华、阶段压力、胜负、重新开始、无尽模式和本地续玩。

保留独立的「房租挑战」，作为后续魔改时的对照入口。当前角色与道具内容采用精选池和原创效果；原版所有符号、道具、精华、成就、楼层规则的逐项覆盖仍需另行列出内容清单，不能用「循环完整」代替「原版内容全量」。

### 阶段 B：星铁包装与移动端

角色作为 Symbols，普通奇物作为 Items，条件触发的奇物精华作为 Essences。更换所有原版美术和文案，增加角色头像、敌人视觉、星空战场与伤害反馈。清晰记录第三方头像的来源、许可文件和文件校验值。

桌面与手机共享同一规则。手机竖屏保持五列关系，选择奖励、查看队伍、查看羁绊、移除角色和继续游戏都能触屏完成。

### 阶段 C：战斗与自走棋融合

增加「模拟宇宙」模式：五列敌人、固定中列 Boss、3 / 2+1 / 1 倍范围攻击、敌人技能、护盾与耐久、关卡期限。不同角色身份触发词条羁绊，三份相同角色升星。12 次遭遇形成首轮可玩的终点，继续无尽以测试构筑成长。

## 当前消歧约定

这些是让首版可执行的暂定选择，后续可以调整。

| 脑暴中未限定的地方 | 首版选择 |
| --- | --- |
| 最近列距离相同时打哪边 | 左侧优先 |
| 重新选主目标后扩散中心在哪 | 实际主目标列，左右各一列 |
| 「周围 2 列」是否指左右各两列 | 主目标左右各一列，共两个旁列 |
| 羁绊是否按相同角色的副本数量计数 | 按不同角色身份计数 |
| 羁绊检查库存还是当次上场 | 检查永久队伍，邻接技能检查当次棋盘 |
| 2 星以后能否继续合成 | 三个 2 星合成 3 星，3 星封顶 |
| 不同星级能否混合升星 | 只合并相同身份且相同星级的三份 |
| 单列是否可以堆叠多个敌人 | 首版每列一个当前目标 |
| 战斗替换是否删除经济模式 | 保留两个入口，用于规则对照 |

## 后续可以直接追加的方向

- 扩展角色与奇物池，每个角色有能辨认的构筑用途，避免只有数值差别。
- 给敌人技能补充意图预告和更清晰的视觉表现，区分干扰、护盾、虚弱与蓄力。
- 探索随机上场和固定站位的关系，比较羁绊按库存与按当次棋盘计数的体验。
- 对战斗伤害、耐久、关卡期限、升星倍率和奖励节奏进行多局数值测试。
- 评估元素弱点、击破、追加攻击、持续伤害、终结技等扩展，决定哪些服务转轮构筑。
- 逐项建立原版功能覆盖清单；新增原版机制时仍使用项目自己的代码、文案与素材。
- 补充音效、图鉴、解锁进度与挑战变体，按试玩反馈决定优先级。
