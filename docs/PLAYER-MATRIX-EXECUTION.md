# 玩家矩阵执行说明

本次依据用户2026-10-26确认的1A标准方案执行，基准为已发布v0.8.1。方法与预算见[实验协议](PLAYER-MATRIX-PROTOCOL-DRAFT.md)。本分支增加实验工具，不改变数值、默认AI或游戏版本，不发布替换版HTML。

## 执行顺序

1. `npm run matrix:preflight`：语法/资源、全部行为测试、生产构建、48局发行引擎逐动作一致性、96状态策略资格和统计校准。任何一项失败不得进入正式阶段。
2. `npm run matrix:standard`：P0三种调度复验→P1全矩阵→冻结P2问题→新种子确认→P3入口检索→五分支筛查→冻结P3问题→新入口确认→本地报告。无需人工在每阶段手动筛题。
3. `npm run matrix:status`：读取进度与实际吞吐。P0计时与集成smoke不进入平衡结论。正式结果未完成时不能把局部排名作为验收。

缺省使用8个worker（每worker旧生代堆上限512MiB），协调进程以8GiB堆预算启动；原始记录存放在被Git忽略的`.local/player-matrix-v1/standard-20261026/`；可审阅的资格、问题登记、摘要与报告在`report/player-matrix-v1/`。工作目录、原始路径、Node/V8版本、硬件与文件SHA都写入实验记录。不会上传到新的外部分析服务。

## 断点恢复与数据身份

再次运行同一命令，会验证源码/策略、全部任务计划、分叉入口索引及已完成分片SHA；匹配才继续，不能将同样任务数但不同策略/问题的旧记录混入。原始目录、阶段目录与报告目录均持有排他写锁；报告目录绑定唯一实验，不能由另一个实验混写。源码变化必须使用新的原始及报告目录，结构异常修复后重测对应阶段，不伪造完整。

每500条完整局或1000条续局写一个流式压缩分片；先写临时文件，再原子提交清单。进程中断后只重复未提交的分片，不重复计算已验证分片。动作上限、无进展、异常或账本不守恒会停止批次，不能静默记输。

过程入口按世界顺序选取，先确定正常策略确实会使用资源，才保存完整快照。入口以单条gzip保存，索引只含身份、位置和SHA，worker按需载入，避免复制全量入口快照。A分支的第一行为流必须精确重现根续局；第二行为流明确重新抽取未来选择。移除错失持续至下一次真实转动，重掷错失持续至奖励选定。E在恢复后至首受影响关的后两关内改用积极R，再恢复原R。

## 输出及判读

- `validation/preflight.json`及各资格报告：方法是否能进入正式采样，含旧bootstrap的校准问题与修复，不代表游戏平衡。
- `pilot-summary.json`：实际吞吐、单局耗时、内存与压缩字节数，给出P1耗时/磁盘估计。
- `screen.json` / `screen.details.jsonl.gz`：逐格和逐关探索，16个世界/格，不能据此确认细小差异或等价。
- `p2-registration.json` / `confirmation.json`：开新种子前登记的问题、成对差与交互的独立确认。
- `fork-*-entry-coverage.json`：合法/意图使用入口的实际覆盖、各H根策略混合与缺样。
- `fork-screen.json` / `p3-registration.json` / `fork-confirmation.json`：一次、整关、持续错失与补救在当关和后两关的风险差。
- `index.html`：可离线打开的逐关压力、策略差异、过程结果与待解决问题报告。原始明细保留在本地。

全矩阵概览JSON、完整统计明细及离线HTML体量较大，仅保存在本地；Git保留生成器、问题登记与小型审计证据。报告模板通过1200/390/320纯静态结构合同检查；file协议浏览器预览被工具安全策略拒绝，因此桌面/手机截图和移动实机验证仍未完成。

所有生存率按开局分母展示，压力/资源条件统计同时列到达和清关分母。自然矩阵描述关联，过程分叉描述登记机会处的策略总效应。游戏数值的任何后续修改须先让用户审阅结果与问题。
