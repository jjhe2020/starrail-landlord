# 规则引擎

0.4.0 的负面条款资格从当前持有的角色、奇物、已解锁精华及激活羁绊的效果元数据识别，覆盖扩充池。已领取的 acquire 治疗不作为持续医疗来源；相邻/定向同谐审查不凭只有全队型支援抽取，角色专属条款仍只作用于指定旧角色。羁绊征收只在当前档有额外威力或追加伤害时入池，实际削减这些进攻收益，不削减资源、护盾、治疗、控制和触发次数。保留旧条款的保存文案以兼容旧 v2 存档，范围补充由界面说明与本段记录。

更新日期：2026-10-15。当前版本只提供五列战斗，游戏存档版本为 `SAVE_VERSION=2`。交租模式已移除，旧报告不代表当前规则。`src/engine.js` 是不依赖 DOM、网络或时钟的 ES module；内容数据提供 64 名角色、64 件奇物、32 种奇物精华和 21 种羁绊。精华内部仍使用 `ESSENCES`、`essence` 阶段与进度字段。新增内容通过 `src/effect-rules.js` 的共享纯规则助手执行，羁绊的配置、人数与档位由 `src/synergies.js` 提供。

## 对外 API

成功动作返回完整的新状态，不修改输入；非法阶段、无效索引、资源不足或没有实际收益的购买返回原状态。

| API | 行为 |
| --- | --- |
| `newGame({seed, difficulty=10, resourceAccess})` | 创建战斗局；难度为 D1–D20，四类资源默认启用 |
| `spin(state)` | 仅 `ready` 转动，消耗一个回合并结算当前遭遇 |
| `chooseReward(state, index)` | 收取当前奖励、处理自动合成及后续奖励 |
| `skipReward(state)` | 跳过当前奖励，按同一阶段队列推进 |
| `rerollRewards(state)` | 奖励阶段刷新候选；先用免费次数，否则花 8 信用点 |
| `removeSymbol(state, uid)` | 在准备或奖励阶段花一次机会移除具体实例 |
| `purchaseSupply(state, kind)` | 准备阶段购买 `repair` / `barrier` / `overclock` |
| `continueEndless(state)` | 第 12 关胜利后进入第 13 关，保留当前构筑与难度 |
| `getSynergies(state)` | 返回所有羁绊的 `count / active / tier` |
| `validateSave(value)` | 校验或迁移，返回 JSON 兼容副本；无效数据返回 `null` |
| `getSaveStatus(value)` | 返回 `valid`、`migrated`、`legacy-classic` 或 `invalid` |
| `nearestEnemy(enemies, col)` | 最近存活列，同距离优先左侧 |

棋盘常量为 `BOARD_COLUMNS=5`、`BOARD_ROWS=4`、`BOARD_SIZE=20`；`STAR_MULTIPLIERS=[0,1,3,9]`，`FINAL_FLOOR=12`。`DEFAULT_RESOURCE_ACCESS` 和 `SUPPLIES` 是资源权限与补给数据。

`src/app.js` 执行玩家与代打动作并存档；`src/ai.js` 只返回决策，不修改游戏；`src/simulation.js` 使用同一动作在独立状态上运行。`src/mechanics.js` 与 `src/inspect.js` 负责说明，不参与结算。详见 [AI.md](AI.md)、[DESIGN.md](DESIGN.md) 和 [TESTING.md](../TESTING.md)。

## 编队、棋盘与攻击

每次从 `roster` 不放回随机抽取最多 20 个实例，再摆入 5×4 的 `board`。超过 20 位时，只有抽中的角色本轮生效；相邻指周围八格，行末不会与下一行行首相邻。

每个实例记录 `uid / id / stars / growth / ticks`。三位同身份、同星级的永久实例自动合成，三星封顶，基础威力倍率为 1 / 3 / 9，保留三份成长总和。羁绊看整个永久编队的不同角色身份，重复副本、不同星级与临时角色不增加人数。桑博生成的临时虎克下轮起参加抽取，登场三次后退场，可提前被消耗，不参与永久合成。

| 攻击 | 结算 |
| --- | --- |
| 单体 | 对本列存活敌人造成威力×3；空列寻找最近存活列 |
| 扩散 | 实际主目标×2，主目标左右相邻列各×1；相邻空列不补伤害 |
| 群体 | 每个存活敌人各×1，同一攻击不重复命中同一敌人 |
| 辅助 | 提供治疗、护盾或增益，本身不直接攻击 |

按棋盘格序攻击，击破后后续角色重新选择目标。伤害只记敌人实际生命减少，溢出不计。角色、星级、成长、邻接、羁绊、奇物、精华、超频与敌方条款共同修正本次威力。

辅助增益与实例成长是不同数据：艾丝妲、布洛妮娅、佩拉、停云和卡芙卡只改变本次局部 `powers`，下次转动重新计算；同一轮不同来源可加算。永久成长写入对应实例的 `growth`，跨转动、跨关保留，移除实例后消失，合成保留三份总和。星级放大多数角色的数值技能，但不把概率、倍率或普通成长量乘 1/3/9。停云保留旧规则：按结算到她时的当前威力选择最高的另一位登场角色，平手优先棋盘较前格；可能选辅助。

护盾是可消耗存量：跨轮、跨关保留，上限为生命上限两倍，普通抵伤扣除；只有当前关存在 `shield_decay` 才在转动开始衰减，不存在全局默认衰减。治疗即时增加生命，溢出通常舍弃；罗刹等明确的转盾能力例外。

## 可执行效果数据

每个内容条目的 `effects` 是有明确时序的效果数组。旧 24 角色、20 奇物、8 精华的解释条目带 `legacy:true`，继续由原对应规则执行，通用执行器跳过，避免重复结算。新 40/44/24 内容使用同一套执行机制；存档里附带的任意效果描述都不能创建新能力。

| 字段 | 含义 |
| --- | --- |
| `type / value` | 操作类型与基值；没有任意脚本或动态表达式 |
| `trigger` | `appearance / spin / floor / acquire / retire / kill / merge / passive / retaliation` |
| `duration / summary / stacking` | 向玩家说明结果寿命、作用与叠加；不会据此生成一个可伪造的永久状态 |
| `target / filter` | 自身、八邻接、全队、匹配角色、最强另一角色或来源列；筛选命途、属性、阵营、攻击类型、临时性与星级上下限 |
| `condition / conditions` | 一条或多条 AND 条件，基于公开生命、护盾、余额、登场计数、回合、关卡、邻居、出场、编队、存活列等数值 |
| `per` | 按公开计数或实际结果缩放，支持除数、上限与可选整档；不写 `floor:true` 时允许小数比例 |
| `chance / every` | 概率经过状态种子随机数；周期登场用实例 `ticks`，其余用本关 `round` |
| `scaleWithStars` | 明确将数值乘来源角色当前星级倍率；概率和倍率本身不放大 |
| `scope:'members'` | 以本轮符合羁绊标签的各登场实例为来源；击破事件只检查实际击破者 |
| `stage / oncePerSpin` | 常规攻击前后、反击后等实际钩子；封顶记在本次局部集合，角色来源与全局来源分别计数 |

当前支持 22 类机制：威力平加/倍率、治疗、护盾、永久成长、信用点/重掷/移除资源、反击固定/倍率减伤、无视装甲、临时召唤、自耗生命、生命上限、额外转动、自然治疗/护盾/辅助/成长倍率、招募稀有度权重、精华进度倍率、能力伤害、临时消耗、治疗溢出转盾。纯助手 `effectAmount / effectConditionMet / effectIsEligible / effectTargetIndexes / getEffectSources` 可同时供规则与 AI 使用；AI 可传公开期望指标替换预测量，真实引擎不使用该预测参数。

新辅助和常驻加值也只计算本次威力；新成长能力修改真实实例。临时角色的最后一次登场虽然已标记 `status:'expired'`、剩余次数为 0，仍以临时角色参与本次加成与攻击，随后退场，不能临时变成永久身份。

## 一次转动的结算顺序

1. 消耗一次回合并新建本次快照；先加入回合门槛触发的首领条款，再执行已有护盾衰减。
2. 抽取并摆放棋盘。污染目标若登场，先绕盾消耗 6 生命；归零立即结束，不能被同轮支援复活。
3. 读取当前永久编队激活的羁绊，按棋盘格序处理角色登场计数、成长、自耗、治疗/护盾、减伤、召援与消耗。`appearance` 条件按其来源实际处理时点检查；一个角色的后续条目能看到自身较早治疗或资源结果。
4. 临时实例次数减一；到期实例本次仍可攻击，提前被消耗实例不攻击。汇总退场，执行 `retire` 与 `spin` 钩子、奇物的即时治疗/资源/本次随机奖励，再读取常驻条件效果。
5. 构造基础威力、永久成长、原生条件加值与早期倍率；按棋盘顺序处理原有邻接/定向支援，再应用通用效果的本次平加和倍率。最后应用奇物、精华、敌方条款、超频及中列干扰。所有临时加值都留在局部数组中。
6. 消耗待用超频，按格序进行常规攻击。常规击破即时触发 `kill`（巡猎追击、物理经营等），这些能力伤害不再次递归触发击破能力，避免无限连锁。
7. 执行角色、奇物在前面排队的能力追加伤害，再执行 `stage:'afterAttacks'` 的羁绊。所有全队破甲支援已先处理完毕，追加伤害仍对实际存活目标结算，不会重复攻击已消失目标。
8. 存活敌人反击，应用固定与倍率减伤，再分贯穿和护盾抵挡。若仍存活，执行 `retaliation / afterRetaliation`，例如按本轮真实抵伤反击；致死不反击、不复活。
9. 从编队删除消耗/到期临时实例，加入下一次才可抽取的召援；更新真实统计。仍存活才积累精华并触发，进攻被动从下次转动起生效。常规或能力造成的实际击破均计精华击破进度。
10. 按首领生命追加后续条款，判定失败或过关并推进奖励。换关重新配置条款，执行 `floor` 一次；打开页面、读取说明或存档不会重发入关奖励。

## 21 种羁绊

`getSynergies` 委托 `getSynergiesFor(state, characterById)`，返回当前人数、档位、匹配筛选与当前档的真实 `effects`。高档替代低档，不叠加两个档位；是否编队达标与本次是否有相应成员实际登场分别计算。已移除旧版对多数标签统一加百分比的通用分支。

新机制覆盖相邻混编、击破回盾、登场周期实验、猎手同场追击、实际治疗转盾、击破追猎、半血爆发、空列集火、偶数轮震荡、真实抵伤反击、治疗减伤、来源辅助放大、不同冰身份减伤、跨列电弧、开局爆发、残敌收割、三身份量子合击、物理击破信用点、虚数减压、临时召援协作和公司入关经营。具体门槛与系数只有 `src/synergies.js` 一处配置；同行者、显示和 AI 共用。

香涎干酪与羁绊征收只修正羁绊的进攻部分：威力平加、伤害或倍率高于 1 的增量；不放大护盾、治疗、信用点、控制、触发次数或时限。

## 难度与遭遇

`difficulty` 与 `floor` 独立：所有 D1–D20 都可直接选，默认 D10，不需要解锁。UI 只提交整数；引擎把有限数值四舍五入后限制在 1–20，未提供或非有限值使用默认值。一局途中及无尽沿用所选难度。规则快照来自 `src/difficulty.js` 的 `DIFFICULTY`，规则标识为 `difficulty-v6`。

敌人总生命预算使用：

```text
base(f) = 40 + 20f + 3f² + 5 max(0,f−2)³
p = lowerDifficultyPivot
level(D) = baseHealthScale × difficulty10HealthMultiplier
           × difficultyStepMultiplier^((max(D,p)−10)/2)
           × lowerDifficultyStepMultiplier^((min(D,p)−p)/2)
late(f) = 1 + (combatLateHealthMultiplier−1) × clamp((f−3)/9,0,1)
total = round(base(f) × level(D) × late(f)
              × (f>12 ? 1.12^(f−12) : 1))
```

当前 `difficulty-v6` 使用公共连续分段生命曲线：D≥6 为 `0.25×1.235^((D−10)/2)`，D<6 为 `0.25×1.235^(−2)×1.22^((D−6)/2)`。系数严格递增；整数生命不下降，极小早期遭遇的相邻档位可能因取整相同，每两档真实总生命增加。D2 / D4 / D6 / D8 / D10 约为 0.110125 / 0.134353 / 0.163910 / 0.202429 / 0.250000，D20 约为 0.718249。第 4 关起的后程系数线性增长至第 12 关的 1.5，无尽延续每关 1.12。所有资源配置共用公式，敌人攻击与条款不按资源开关作弊调整。

历史 0.3.0 的 [v6 独立报告](benchmarks/resource-balance-v6.json)使用旧 B=1.12 生命曲线与当时的 `resource-actions-v5`，完整 D10 为 969/1,000；这是 24/20/8 内容及旧羁绊的数据，不能当作 64/64/32 与新羁绊的当前胜率。九组防御规划观察也未证明实际缺少防御，原报告完整映射 `target.passed=false` 保留。当前批次的实测、算法标识、样本与限制见 [AI.md](AI.md) 和 [BALANCE.md](BALANCE.md)；历史 [v4](benchmarks/resource-balance-v4.json) / [v5](benchmarks/resource-balance-v5.json) 不代替新报告。

第 1 关占第 1、3、5 列，第 2 关占第 1、2、3、5 列，以后占五列。每三关有中列首领，普通列权重 1、首领列 2.2。总生命先取整，各列先向下取整，再按小数余量降序分配余额，同余量优先左列，分配总和等于总预算。敌人基础攻击为 `1+floor(f/4)`，首领再加 2。

第 1–4 关有 5 次转动，第 5–8 关有 6 次，第 9 关起有 7 次；「公司咕咕钟」（稳定 ID `seal_stamp`）从新关起增加一次。角色行动后，存活敌人反击，普通伤害先扣护盾再扣生命；贯穿条款可以绕过部分护盾。初始生命 100，护盾上限为生命上限两倍，可跨关保留。生命归零或到期仍有敌人立即失败，清空后补给 `8+floor×3` 信用点。第 12 关直接胜利；无尽继续敌人生命增长、普通条款与每三关首领，不增加交租规则。

## 敌方技能与 32 条负面词条

原有四种遭遇技能继续生效：周期增伤、逐次命中装甲减伤、中列减益、周期额外攻击。它们独立于 `src/enemy-effects.js` 的 32 条负面词条。31 条普通词条针对命途、攻击类型、成长、邻接、升星、召援、具体角色技能、精华、羁绊及自然防御；另有固定实例词条「裂界污染」。词条实际接入对应结算，不永久禁用角色或清除构筑。

普通词条从当前编队具备的机制中筛选，不重复抽取，不把已关闭的实验开关当作额外敌方惩罚。从配置的 `debuffStartFloor` 起加入普通难度条款。首领入场为阶段 1 并加入一个适用条款；生命降至 70% / 35%，或回合达到 3 / 5，可推进至阶段 2 / 3，追加适用且未出现的条款。没有适用项就不追加。回合触发先于护盾衰减与棋盘抽取，因此当轮新加的衰减条款当轮就执行；攻击后的生命阈值追加在本轮结算末尾，从后续回合影响结算。界面写「第 X 次转动时追加」，不把追加时间统一称作生效起点；过关重新配置。

`activeDebuffs` 保存 `id / name / description / source / addedRound`，`source` 为 `boss` 或 `difficulty`；`bossStage` 为 0–3，`bossStages` 保存阈值与三阶段上限。UI 显示当前条款、阶段和新增提示，准备及奖励阶段均可查看说明。

「裂界污染」只在第 4、6、8、10、12 关入场时配置，不进入普通随机池，也不自动扩展到无尽的其他偶数关。选永久一星实例中 `基础威力+已有成长` 最低者，同值按 uid 的英文字符串顺序决定；没有合适实例就不添加。额外保存 `targetUid / targetId / targetName`：

- 仅这个实例实际抽上棋盘时，直接消耗最多 6 点剩余生命，绕过护盾；本轮所有攻击角色的最终威力统一乘 0.85，标记实例自身再乘 0.5，因此它作为攻击角色时合计乘 0.425。
- 全队攻击折价每轮只应用一次，同名副本也受这一次全队折价；辅助治疗、护盾与增益不折价。棋盘只标记触发实例，不把全队都标成污染目标。
- 没有抽中，不扣生命，也没有全队折价。扣到 0 立即失败，在角色治疗或精华结算之前结束，不能同轮复活。
- 移除或合成消耗被标记实例后清除，不在本关另挑替代目标；换关也清除。
- 所有资源配置使用同一真实污染规则；关闭移除仅失去解除手段，不额外制造伤害。

## 奖励与四类资源

每次普通转动后先招募；每完成两关附加奇物、每完成三关附加精华，队列为招募→奇物→精华。每阶段通常三项不同候选，也可跳过；已拥有的奇物/精华排除，候选不足时按实际数量提供，没有可用奖励时转为 10 信用点。精华从取得后的下一轮积累，到阈值触发一次。初始重掷 2、移除 2；进入新关补一次重掷，偶数关另补一次移除。

福灵胶与新增稀有度倍率只调整招募角色候选权重，不影响奇物或精华。这里修正了旧版福灵胶意外影响全部奖励池的问题，与其“招募权重”说明保持一致。

每个新精华的 `progress.metric` 明确积累条件。伤害、转动、登场、实际治疗/护盾、成长、退场、击破及转动内信用点直接使用本次真实量；`rerolls / removals / creditsSpent / merges` 在取得时保存当前累计计数为 `baseline`，每次转动末只增加之后的新差量，并推进基线，不能重算取得前的操作或重复记账。未触发精华的增量受缓释条款与持有进度倍率影响。

所有精华在达标奖励结算前读取同一份本次转动计数与已有进度倍率。精华当场发放的信用点、治疗或护盾会真实入账，但不回流为另一精华的同次蓄能；新解锁的精华进度倍率从下一次转动参与蓄能。调整精华取得顺序不会改变这些进度。

原丰饶精华保留自然治疗语义：只触发一次，永久生命上限+20，当场治疗相当于新上限的基础生命，受自然治疗倍率和医疗折价影响，不保证回满。原存护精华仅累计转动内实际生成护盾，上限截断不计；两次转动之间的护盾补给和新关赠盾不计此进度。触发后的进攻增益从后续转动开始，一次性资源奖励不会每轮重发。

| `resourceAccess` 键 | 关闭后的行为 |
| --- | --- |
| `rerolls` | 免费与付费重掷均不可用 |
| `removals` | 不可移除实例 |
| `credits` | 不可付费重掷或买补给；仍会获得信用点，免费重掷可用 |
| `defense` | 关闭主动防御规划并禁用医疗/护盾补给；自然治疗、护盾、生命上限增益、抵伤和承伤均保留 |

防御规划开关还令 AI 本局的有效防御权重为 0，不改保存的档案权重。它不能解释为生命与护盾完全从游戏中消失，实际是否有效使用必须看统计。

| 补给 kind | 成本与效果 |
| --- | --- |
| `repair` | 12 信用点，恢复 18 生命，不超过上限；满生命不可买 |
| `barrier` | 10 信用点，获得 20 护盾，不超过上限；满护盾不可买 |
| `overclock` | 16 信用点，下次转动威力×1.2，用后消耗；待用时不可重复买 |

三种补给只在 `ready` 购买，共用每关两次限额，换关清零 `supplyPurchases`。维修与护盾补给固定数值不被普通治疗/护盾折价词条缩减，上限截断部分不算实际获得。超频不叠加；买补给不消耗转动回合。

## 资源统计、存档与展示字段

`resourceStats` 记录真实累计量：`initialHp / initialShield / rerollsUsed / paidRerolls / removalsUsed / supplyPurchases / creditsSpent / healed / shieldGained / shieldBlocked / shieldDecayed / hpLost`。与 `state.supplyPurchases` 不同，`resourceStats.supplyPurchases` 跨关累计。`healed` 与 `shieldGained` 只算实际上限内增加；`hpLost` 包括实际反击、直接污染和角色自耗生命，`shieldBlocked` 只算抵伤，`shieldDecayed` 是衰减浪费。初始量也计入生成基数。效率定义和批量汇总见 [AI.md](AI.md)。

游戏随机数经过持久的 xorshift32 `rngState`。相同规则、难度、资源配置、种子与操作可复现；跨规则版本不保证从第一关重开同一旅程。UI 从 localStorage 读取后先校验，再交给渲染器。校验覆盖有限数值、阶段/奖励队列、棋盘尺寸、重复 uid/敌人/奖励、临时状态、条款来源与污染目标、补给及难度字段，拒绝损坏局。

有效 v1 战斗存档迁移到 v2、D10 和全资源权限，保留当前敌人、棋盘、奖励、随机状态与进度，不重新抽取遭遇。当前遭遇不补抽新条款，后续新关使用新规则；统计从迁移时的当前生命/护盾开始，不伪造迁移前生成与消耗。`migratedFromVersion=1` 标明迁移并保留在 v2 中；页面只在原输入为 v1 且迁移成功时提示一次，重新读取已迁移 v2 不重复提示。v1 交租存档返回 `null` / `legacy-classic`，UI 明确提示模式已移除并引导新战斗，不偷偷转换进度。

早期 v2 存档中的旧污染说明，只在文本完全匹配已知旧格式与目标名字时规范成当前说明；继续保留旅程、敌人、UID、资源、难度与 RNG，不视为 v1→D10 迁移。任意其他伪造污染文本仍拒绝，状态版本仍为 2；原说明更新后，后续实际转动按当前全队攻击折价规则结算。

扩容不升级存档版本：新增字段均兼容旧 v2 缺省。新精华可选 `baseline` 必须属于累计指标、为有限非负数且不超过当前对应计数；缺少时只在返回副本中补为当前计数，避免补发历史进度。精华对象拒绝未知机制字段。`lastSpin` 的可选效果记录与威力分解严格检查结构、长度、数值及最终值一致性；它们只供展示，执行器仅从已校验内容 ID 查当前定义，不读取快照来赋予能力。

展示字段：

- `lastSpin.values[0..19]` 为上次已完成的威力结算，`hits` 为实际 `cell / targetCol / amount` 命中（最多 1,024 条）。新关、奖励选择或查看说明不会重算旧棋盘，它不是下次抽取的预报。
- 新快照 `floor / round` 记录结算发生的上下文；旧 v2 可以缺少，不应猜成当前关。
- `lastSpin.effects` 最多 2,000 条，只记录展示数据：`sourceId / sourceUid? / targetUid? / type / label / duration / amount? / floor? / round?`。每条新事件带实际发生的关卡和转动次数，避免把过关后的奇物取得、入关预算误标为旧棋盘上的效果；旧记录可缺省。来源、永久成长、辅助和负面时效可查；缺少记录不改变实际规则。它不会在重载时重放。
- `lastSpin.powerBreakdown` 长度 20，空格为 `null`，其余为 `base / growth / beforeMultiplierBonus / baseMultiplier / flatBonus / multiplier / final`。`base` 已含星级；公式为 `((base + growth + beforeMultiplierBonus) × baseMultiplier + flatBonus) × multiplier`，最后按两位小数舍入。阿兰、青雀等早期倍率单独记录，不伪装为平加；后续辅助只计 `flatBonus`。此分解解释计算顺序，不反推每种临时来源的独立伤害贡献。
- 合成后的 `multiplier` 保留计算精度，避免先把倍率舍入再乘永久成长造成明显差额；辅助效果日志的数值记录星级、奇物和敌方折价等调整后实际施加的增益。界面显示仍可做数值格式化，分解项的展示舍入可能产生微小差额。
- `lastSpin.damage / coins / healing / shield / incoming` 为本轮结果；`shield` 只算实际增加，`incoming` 为角色减伤后的反击总量，护盾随后继续抵挡。
- `enemyIntent` 是存活敌人的下一轮基础预告，不能精确预言尚未抽出的角色与后续阶段变化。
- `board` 可保留退场展示快照；已消耗角色不再攻击，正常到期角色本轮行动后退场。
- `pendingFloor / pendingRewards` 保证过关奖励只推进一次；`history` 为操作记录，`stats` 为累计转动、伤害、获得信用点、合成与退场统计。

网页与单文件版使用同一引擎。浏览器沿用兼容存储键 `astral-reels:v1`，内部 `game.version` 为 2。单文件版的存档交换包 `format='astral-reels-save'` 的格式版本仍为 1，与内部游戏状态版本不同；导入同时校验游戏、统计、设置和 AI 档案。更新 HTML 前应导出存档，不同文件路径、版本或浏览器可能使用独立存储。离线实现见 [OFFLINE.md](OFFLINE.md)，验证见 [TESTING.md](../TESTING.md)。
