# 规则引擎

`src/engine.js` 是不依赖 DOM、网络或时钟的 ES module。`src/content.js` 提供 24 名角色、20 件奇物、8 种奇物精华（内部余响机制）与 19 种羁绊。精华以银河大乐透、异木果实及六种命途火漆包装，内部仍使用 `ESSENCES`、`essence` 与余响进度字段；显示名称与机制 ID 分开。内容的描述对应实际生效规则。

## 对外 API

所有动作返回完整的新状态；成功动作不修改传入状态。阶段不允许的动作、越界奖励选择、资源不足的操作直接返回原状态。

| 函数 | 用途 |
| --- | --- |
| `newGame({ mode, seed })` | 新局；mode 为 combat / classic；字符串 seed 可复现 |
| `spin(state)` | ready 阶段转动，结算战斗或信用点，然后进入奖励阶段 |
| `chooseReward(state, index)` | 选择当前奖励，自动处理合成与后续阶段 |
| `skipReward(state)` | 跳过当前奖励 |
| `rerollRewards(state)` | 优先消耗重选次数，否则支付 8 信用点 |
| `removeSymbol(state, uid)` | 消耗移除次数，移除某一个角色实例 |
| `continueEndless(state)` | 十二层胜利后进入第十三层，继续当前编队 |
| `getSynergies(state)` | 返回全部羁绊及 count / active / tier |
| `validateSave(value)` | 完整检查存档，返回 JSON 兼容副本或 null |
| `nearestEnemy(enemies, col)` | 查询距离最近的存活敌人，距离相同时选择左侧 |

其他常量：`SAVE_VERSION=1`、`BOARD_COLUMNS=5`、`BOARD_ROWS=4`、`BOARD_SIZE=20`、`STAR_MULTIPLIERS=[0,1,3,9]`、`FINAL_FLOOR=12`。

0.2.0 沿用上述游戏动作与数值。`src/ai.js` 只返回推荐，不修改游戏状态；`src/simulation.js` 在独立状态上调用同一引擎。页面代打由 `src/app.js` 执行动作并存档，批量实验由 `src/ai-worker.js` 运行，不写玩家当前旅程。机制说明位于 `src/mechanics.js`，就地浮层控制位于 `src/inspect.js`，都不参与规则结算。AI 接口见 [AI.md](AI.md)，实验和命令见 [BALANCE.md](BALANCE.md)。

0.2.1 新增 `src/difficulty.js`：`DIFFICULTY` 记录 `version='difficulty-v2'`、`combatLateHealthMultiplier=1.5`、`classicLateRentMultiplier=1.28`；`lateDifficultyMultiplier(floor, endMultiplier)` 返回 `1 + (endMultiplier - 1) × clamp((floor - 3) / 9, 0, 1)`。实验报告的 `rules` 字段保存这些规则参数；游戏动作与 `SAVE_VERSION=1` 保持不变。

## 棋盘、角色与羁绊

- 持久编队是 `roster`，棋盘是 `board`。每次转动从编队不放回随机抽取最多 20 个实例，再随机放入 5 列 × 4 行的棋盘。编队超过 20 时只有抽中的角色本轮生效。
- 每个实例有 uid / id / stars / growth / ticks。永久成长跟随实例保存，合成后保留三份成长总和。
- 三位同角色、同星级的永久角色自动合成；一星、二星、三星基础威力倍率为 1 / 3 / 9。三星不继续合成。
- 羁绊按整个永久编队中的**不同角色身份**计数。重复角色和不同星级只算一种。登场角色享受已经激活的对应羁绊。
- 同时激活多个羁绊时，羁绊威力增益先相加。奇物与已触发余响的倍率随后相乘。
- 相邻指同一棋盘上周围八格，行末不会与下一行行首相邻。
- 桑博可以生成临时虎克。临时角色下轮起参与抽取，登场三次后退场，不参与永久角色合成或羁绊计数。虎克可提前消耗相邻临时角色，姬子与虫网能够从退场事件获益。

## 两种模式

经典模式每轮按全部登场角色的威力总和向上取整，获得信用点。剩余转动为零时支付本层租金，余额保留到下一层；不足则失败。十二层基础租金依次为 25、45、90、170、300、500、800、1250、1900、2800、4000、5600。0.2.1 以 `round(基础租金 × lateDifficultyMultiplier(floor, 1.28))` 得到实际租金：25、45、90、175、319、547、900、1444、2255、3410、4996、7168。

战斗模式的单体、扩散、群体分别结算为：

- 单体：对应列的敌人受到 3 倍威力伤害；该列为空时寻找最近存活列，距离相同时选择左侧。
- 扩散：实际主目标受到 2 倍威力伤害，主目标列的左右各一列受到 1 倍。空的相邻列不跳跃寻找其他敌人。
- 群体：所有存活敌人各受到 1 倍威力伤害。
- 辅助：提供治疗、护盾或增益，本身不直接攻击。经典模式仍按辅助角色威力获得信用点。

角色按棋盘格序逐个结算攻击；前一个角色击破后，后一个角色重新选择目标。显示伤害以实际扣除敌人生命为准，不把溢出伤害计入统计。

初始生命 100，护盾上限为生命上限的两倍。角色攻击后，所有存活敌人各攻击一次，先消耗护盾再扣生命。敌人存在可预告的四种技能：周期增伤、逐次命中减伤、中列减益、周期额外攻击。银狼或佩拉能够绕过装甲。第三、六、九、十二层为首领层，首领固定在中间列。

第 1–4 层有 5 次转动，第 5–8 层有 6 次，第 9 层起有 7 次；奇物「公司时刻」增加一次。战斗模式必须在期限内清除全部敌人，否则失败。通过后奖励 `8 + floor × 3` 信用点。

敌人基础总生命公式为 `40 + 20f + 3f² + 5 max(0,f-2)³`；0.2.1 先乘 `lateDifficultyMultiplier(f, 1.5)`，再按首领列权重 2.2、普通列权重 1 分配，每列分别四舍五入。前三层不变，第四至十二层线性增压，第十二层完整加成 50%。例如第六层五列生命为 `[111,111,243,111,111]`，第十二层为 `[1382,1382,3040,1382,1382]`；每列取整可能令总和与未取整公式略有差别。该数值是本项目的实验平衡，并非原作数值。

## 奖励阶段

每次转动后先选择三个不同角色之一，或跳过。每完成两层附加奇物选择，每完成三层附加余响选择。顺序固定为招募 → 奇物 → 余响，最后进入下一层；十二层最后结算直接进入胜利阶段。

奖励权重按稀有度抽取，后期提高高稀有度概率。已拥有的奇物和余响不会重复出现。无可用奖励时转为 10 信用点。余响从取得后的下一次转动开始积累，达到各自阈值后永久触发一次。

初始重选 2 次、移除 2 次；进入新层获得 1 次重选，每个偶数层另获得 1 次移除。

## 存档与展示字段

UI 负责把完整状态序列化到本地存储，读取后必须调用 `validateSave`。状态使用 xorshift32 与持久 `rngState`，在相同规则版本下读档后继续操作与未读档一致。0.2.1 保留有效旧存档中当前的敌人和本层租金，不在恢复时重算；下一次进入新层才应用新难度。相同种子复现也要求相同规则版本，跨版本不保证完整旅程一致。

- `lastSpin.values[0..19]`：棋盘每格最终威力；`lastSpin.hits`：实际命中，包含 cell / targetCol / amount，供动画使用。
- `lastSpin.damage / coins / healing / shield / incoming`：本轮结算。shield 只记录实际增加的护盾；被上限截断的部分也不计入余响进度。incoming 是角色减伤后的敌方攻击总量，护盾还会继续抵挡。
- `enemyIntent.damage`：下一轮存活敌人的基础攻击威胁，未计入尚未抽中的角色减伤。
- `board` 会保留刚刚退场的展示快照：consumed 角色不攻击且威力为零；expired 角色本轮仍攻击，之后从编队删除。
- `pendingFloor`：已完成当前层，尚未领完奖励；`pendingRewards`：后续奖励阶段。
- `history`：最近操作日志；`stats`：累计转动、伤害、信用点、合成与临时角色退场次数。

无尽模式保留编队和资源，也保留完整末层难度倍率。第十三层起租金为 `round(5600 × 1.28 × 1.16^(floor-12))`，敌人总生命为 `基础生命公式 × 1.50 × 1.12^(floor-12)`，之后仍按各列权重分配和取整；线性增压进度封顶，不再继续增长。

## 验证

`node --test tests/engine.test.js` 的 26 项引擎测试覆盖确定性、无放回棋盘、三种攻击和回退、装甲、辅助、护盾上限的实际获取量、成长、合成、不同身份羁绊、租金与奖励顺序、截止失败、资源消耗、临时角色生成/消耗/退场、余响、存档拒绝与十二层后无尽。固定种子 `balance-0` 的完整十二层经营与战斗局使用生产 AI 的真实概率抽样和移除，在每个动作后检查可读档状态。`tests/difficulty.test.js` 另有 6 项回归，验证初期不变、线性倍率、生产数值、无尽与有效旧存档；0.2.1 共 51 项常规测试通过，另 1 项浏览器入口默认跳过。

0.1.0 的早期流程抽样使用 100 个固定种子与简单招募策略，战斗通关 93 局、经典通关 59 局。0.2.0 另以生产 AI 和均匀选择策略运行 800 局独立对照：战斗 200/200 与 76/200，经典 199/200 与 16/200；不同策略与种子集的结果不能直接解释为规则变难或变易。完整统计和 3,200 局参数搜索结果见 [BALANCE.md](BALANCE.md)。有限样本与 AI 表现不等于玩家难度或全部构筑已经平衡。

0.2.1 的难度验收以相同 `context-v1`、前瞻与完整概率抽样为基准；每模式独立发布样本为 1,000 局 AI，加 1,000 局均匀选择对照。战斗 AI 967/1,000、经典 AI 946/1,000，均达到约 95%、允许 90%–98% 的目标；调参样本不参与发布胜率计算。规则参数、置信区间与记录见 [BALANCE.md](BALANCE.md)。
