# 0.8.1 玩家版与开发版

更新日期：2026-10-25。本轮将呈现与诊断分开，战斗沿用 0.8。以下是双版本的展示与交付契约；具体执行结果以当次发布验证记录为准，不因本文列出要求而视为已经验证。

## 分层原则

玩家在行动前需要看清目标、当前风险、可用资源及选择会产生的效果。内部分析如何得到结论、实验样本怎样分组、AI 如何打分，属于开发工具。玩家版减少默认展示的同时，保留完整的公开规则查询：对象、空间条件、触发时点、数值、持续时间、叠加和星级缩放都不能成为隐藏规则。

“套路”是内部拿牌偏好或测试代号，不是技能标签。玩家查看的配合依据是命途、属性、阵营、正式羁绊和卡面空间条件；开发版同样不能因测试偏好增加额外奖励。

| 界面区域 | 玩家版 | 开发版 |
| --- | --- | --- |
| 战斗主界面 | 关卡、难度、生命/护盾、剩余转动、资源、敌方意图与行动 | 保留相同战斗与资源信息，可使用开发工具 |
| 棋盘、编队与招募 | 名称、星级、攻击力、默认攻击方式/倍率和技能；正式标签可查 | 在同一规则上增加诊断与推荐信息 |
| 角色、奇物与精华详情 | 完整技能、条件和持续时间可查；复杂规则与结算按需展开 | 可显示完整诊断细节与开发说明 |
| 羁绊与剧情委派 | 真实条件、对象、档位、当前进度与效果可查 | 可额外解释测试背景，不能更改效果 |
| 结算与日志 | 当前战斗结果与实际发生的效果；细节按需查看 | 保留更详细的统计与诊断 |
| 帮助与资源说明 | 先解释如何行动和规则后果；公式与叠加按需查询 | 可查看实验口径、算法限制与测试说明 |
| AI 推荐、分数/概率、代打、训练与试验台 | 不提供入口，也不在招募卡默认显示推荐 | 保留，明确为制作与测试工具 |
| 设置、存档与离线 | 音效/动效、导入导出、保存可用性及必要更新提醒 | 同样保留；测试存储与玩家旅程分离 |
| 素材归属与关于 | 保留同人改编、来源与归属信息 | 同样保留 |

历史版本迁移说明应出现在相关的更新或存档情境，避免反复占据普通战斗与选择界面。离线运行、存档风险和第三方素材归属仍是玩家需要的信息，不能当作开发注释删除。

## 两版共用的规则与存档

两版使用同一 `src/content.js` 与 `src/engine.js`。相同有效状态与明确动作应得到相同引擎结果；版本标记不进入随机抽取、技能条件、敌人强度或胜负判定。开发版 AI 只是替玩家选择公开动作，不赋予特殊权限。

游戏状态版本与存档交换格式保持兼容，两版可以通过 JSON 导出/导入继续同一旅程。玩家版沿用历史自动存档命名空间以保留已有网页进度；开发版使用独立命名空间，避免测试旅程覆盖玩家旅程。不同 HTML 路径、浏览器或设备不保证共享本地存储，更新或切换文件前先导出存档。开发版的 AI 配置不在玩家界面生效为自动操作。

## 构建与交付

`npm run build` 生成静态玩家入口 `dist/index.html` 与开发入口 `dist/development.html`；源码开发服务器同样通过 `/` 与 `/development.html` 进入两版。本轮不自动部署现有 Site。

`npm run build:portable` 默认生成两个独立的完整 HTML：

- `artifacts/星穹转轮-v0.8.1.html`：玩家版，作为默认游玩入口。
- `artifacts/星穹转轮-开发版-v0.8.1.html`：开发版，保留测试工具。

两份文件都内嵌各自运行所需的图片、样式和脚本，首次运行无需联网或登录；开发版所需 AI 也在本地运行。玩家构建排除开发工具。两个文件是同一游戏的两种呈现，不是两套难度或数值版本。每次发布均核对两份准确附件的大小、SHA-256 与实际下载结果。

## 验证边界

需要在桌面与手机屏宽检查两版的主界面、奖励、角色/奇物/精华/羁绊说明、帮助、设置与存档；玩家版需要检查内部词语、AI 推荐及开发入口没有从其他弹窗重新出现。真实规则与高级详情仍可操作、阅读。

最终两份 HTML 都需要首载离线、内嵌资源、动作与保存检查；另验证玩家与开发自动存档分离、两方向导入导出、旧玩家存档恢复。开发版还需确认 AI 推荐、代打与工具可以使用。桌面窄屏或触屏模拟只证明对应浏览器环境，不等于 Android 文件分享入口或 iPad 实机已经验证。

0.8.1 的界面回归不证明持续压力或平衡改善。后续玩家矩阵与压力实验见 [PLAYER-MATRIX-PLAN.md](PLAYER-MATRIX-PLAN.md)；本轮不执行。
