# 本地策略 AI 与资源实验

更新日期：2026-10-16。AI 在浏览器本地运行，不上传存档、不依赖网络模型；使用规则估值、反事实结算与短期试算，不能描述为已收敛强化学习。当前策略 `archetype-actions-v7`，默认参数 `context-v3-resources`。本版加入共享套路效果估值与有限委派供给估值；独立套路偏好、自适应规划及压力测试见 [套路平衡报告](BALANCE-ARCHETYPES.md)。旧版 `resource-actions-v6` 的 97.70% 胜率只作为0.4.0历史记录，不能代表当前内容池。

## 一套动作决策

页面代打与 `runCampaign` 共享 `recommendAction(state, {profile, lookahead})`，实际调用同一个引擎。返回 `type / reason / policyVersion / version`，可选 `uid / kind / cost / estimatedGain / recommendation`：

| type | 调用方执行 |
| --- | --- |
| `remove` | `removeSymbol(state, uid)`，评估稀释、污染实例代价及合成机会 |
| `reroll` | `rerollRewards(state)`，真实免费次数或 8 信用点扣款 |
| `supply` | `purchaseSupply(state, kind)`，受实际成本、收益与两次限额约束 |
| `spin` | `spin(state)` |
| `reward` | 使用返回的 `recommendation` 抽样，按 action 领取或跳过 |
| `stop` | 停止，通常为终局或不可执行阶段 |

决策函数不修改状态，不花资源，也不消耗游戏随机数。调用方必须执行建议动作才改变旅程；奖励分布不能在执行时悄悄换成另一套策略或强制最高分。当前共享决策先检查有收益的移除，奖励阶段再考虑重掷或抽样，准备阶段考虑补给或转动。后续算法以冻结的 `POLICY_VERSION` 为准。

重掷比较当前候选与独立试算新候选的期望收益，计入免费机会的未来价值、信用点成本、补给预算与不确定性，不偷看真正下一组奖励。补给比较实际购买前后的结算，满血、满盾、超频已待用、消费禁用或限额耗尽时不会买。移除可以在未满 20 人时处理有实际代价的污染实例，也会保留有价值的核心与当前可形成的合成；不是无条件削空开局编队。

v5 保留 v4 的共同样本移除确认：对静态估值筛出的最多四个移除候选，使用同一组下一轮引擎试算比较移除前后收益。默认前瞻至少三样本，当前档案为四样本；均值扣一倍标准误后仍须为正，再结合保存移除机会的成本，才执行建议。小样本确认使删除更保守，不构成长期最优或统计置信保证。污染可能在治疗前致死时会优先考虑对应实例；当前可形成的有价值合成仍参与取舍。

## 奖励与跳过的概率

令 `N=state.choices.length`。普通奖励 `index=0..N−1, action='choose'`；跳过追加为 `index=N, id='skip', action='skip'`。招募、奇物、精华三阶段都比较真实引擎选择后的状态，跳过使用 `skipReward` 后状态作为边际基准。N 张奖励加跳过共同用 softmax 归一化，候选不足三张也按实际 N+1 项计算。

卡片的百分比表示**当前奖励决策的选择倾向**，不表示此项通关率、稀有度或中奖率。跳过概率随编队与局面变化，不固定为零或固定占比。`sampleRecommendation` 用原始未舍入概率按累计区间抽样；显示最多两位小数，极小非零值显示「＜0.01%」，显示值合计可能有微小舍入差。

代打可能先移除或重掷，再对新的奖励局面抽样。因此看到某张卡的概率，不意味着下一步必定领取当前候选。卡片说明与实际跳过按钮分开，查看建议不会执行跳过。异步结果必须对应当前状态和候选，迟到结果不覆盖新局面；分析中打开浮层不展示旧具体概率。

## 估值、前瞻与随机流

估值考虑攻击范围与存活列、星级和成长、连锁合成、不同身份羁绊、邻接与技能配合、临时召援退场、治疗/护盾和反击、20 格抽取稀释、奇物搭配、精华触发时间与关卡期限。32 条敌方词条和指定污染实例参与真实结算；关闭资源开关不人为给敌人添加额外惩罚。

默认奖励前瞻使用 4 个随机棋盘，候选用共同的一组试算种子减小比较噪声。种子来自公开局面，明确排除真实游戏 `seed / rngState` 与未揭示奖励；在反事实选择与转动前替换副本随机状态。重掷和补给也用独立试算，原局随机流不变。估值仍是短期近似，不保证找到全局最优构筑或最高理论胜率。

v5 的静态估值按不放回抽样计算全队攻击折价。编队共有 N 个实例，某角色已知登场时：若它就是标记实例，触发概率为 1；若它是其他实例，N>20 时标记实例同时登场的条件概率为 `19/(N−1)`，N≤20 时为 1。全局抽中标记实例的概率仍为 `min(20/N,1)`，不能把这个无条件概率重复用于已经登场的角色。攻击折价及其他已知本关条款按剩余本关占长期回合的比例计入，不永久外推到后续关卡。随机引擎试算使用实际抽取与一次性全队折价，不用静态概率代替真实结算。

长期治疗估值包含真实生命缺口、反击余量，以及护盾不能代付的刃自耗与本关污染代价；污染生命代价同样只覆盖本关。持续回合估计不能精确保证随机落位的治疗先后或未来补给。下一轮真实引擎试算保留角色顺序、治疗上限、未抽中不扣污染生命及治疗前致死条件；满盾也不等于不需要治疗。静态条件概率提高了抽样口径准确性，仍不构成长期最优保证。

策略抽样使用 `createPolicyRandom` 的独立流。完整模拟在相同源码、规则参数、状态、档案、游戏种子和策略种子下可复现。游戏引擎 RNG 随存档保存；页面在初始化、新局或导入时重新创建策略抽样流，因此不承诺刷新后续代打与未中断代打拥有完全相同的随机选择序列。玩家执行相同明确动作时，引擎续档仍可复现。

## 0.4.0 共享效果估值

新增角色、奇物和精华从 `effects` 声明中评估真实触发频率、条件、目标、概率、星级、成长、生命周期及一次性资源；21 种羁绊与真实引擎共用 `tierEffects`，删除旧的通用羁绊百分比表。不同身份同场条件按不放回抽样概率估计；达到永久编队门槛不等于本轮一定取得收益。数值倍率的随机期望按增量计算，不能把整个乘数乘概率。新奖励仍与跳过共同归一，不存在强制选新内容的规则。

## 四类资源与实际防御使用

实验开关为 `rerolls / removals / credits / defense`。前三者分别限制重掷、移除及信用点支出。`credits=false` 仍可获得信用点，免费重掷也可用；`rerolls=false` 则免费和付费重掷都禁用。

`defense=false` 表示取消主动防御规划：本局有效防御估值权重为 0，禁止 `repair / barrier` 购买，保存档案本身不变。角色、奇物、精华、羁绊自然产生的治疗、护盾、生命上限增益及正常承伤仍按引擎生效。该开关不能证明防御资源没有实际有效使用。

`resourceStats` 记录实际累计量，`summary.avgUsage` 为逐局平均，`summary.defenseUsage` 使用**全批总量**：

```text
hpGenerated     = initialHp + healed
shieldGenerated = initialShield + shieldGained
hpConsumed      = hpLost
shieldConsumed  = shieldBlocked
hpConsumptionRate     = hpConsumed / hpGenerated
shieldConsumptionRate = shieldConsumed / shieldGenerated
combinedRate = (hpConsumed + shieldConsumed) / (hpGenerated + shieldGenerated)
```

生成只算实际增加，不含上限截断；初始生命和护盾计入基数。生命消耗包含真实受伤、污染和角色自耗；护盾消耗只算实际抵挡伤害。`shieldWasted=shieldDecayed` 是条款衰减浪费，不进入有效抵伤分子。分母为零时引擎统计率为 0，界面说明为未生成。迁移旧存档的统计从迁移时当前量开始，不能与全新完整局直接混为相同观察周期。

`classification` 当前用暂定观察阈值：`combinedRate<0.2` 为 `low`、`>=0.5` 为 `effective`，其余为 `moderate`。20% / 50% 是暂定分类，不是用户硬性比例要求，也不是规划器的奖励目标，不鼓励为了提高效率故意承伤。

汇总的 `combinedRate` 是总消耗/总生成，不是每局百分比平均。`effectiveRate` 是逐局达到有效阈值的比例，`lowRate` 是偏低局比例；`resourceUsageRates.defense` 使用实际 `effectiveRate`，不按资源开关把关闭规划局强记为零。其他三类使用率看真实重掷、移除与信用点消费发生的局数。

如果防御规划关闭但实际防御仍有效，报告必须标明：这是规划开关对照，不能当作缺防御的档位验收。名义禁用数、真正有效使用和难度档位分别报告；胜率检查通过不能单独证明四类资源均有可解释的作用。

`assessResourceVariant` 根据平均实际次数判断重掷、移除、信用点是否参与，以总量防御比例低于暂定 20% 判断防御使用偏低，并返回 `actualMissingResources / actualMissingResourceCount`。这里 20% 判断参与/缺失，50% 判断充分有效，不能混成一个阈值。`nominalDifficulty` 按实际缺失数量计算，只有实际资源和声明开关一致才有 `nominalMappingEligible`；`verifiable / passed / reasons` 分别表示可验收性、验收结论和原因。完整 D10 的当前校验还要求主动三类确有消费、防御总量比例达到暂定充分阈值。D10 防御规划关闭行明确不可作为彻底移除防御的消融；整体 `target.passed` 不因其余行通过而变成成功。

`defenseUsage.strata` 按每局赛后消耗比例分为 `low / moderate / effective`，包含 n、胜局、胜率区间、生成/消耗总量、各资源参与率与 `jointActiveFour`。四资源共同参与样本中的防御参与按暂定 20% 判断，充分有效仍用 50%。这些行带 `observational=true`，是观察分层，不是随机因果对照；高消耗可能同时伴随失败，必须看样本数与分层胜率。

## 对照、资源矩阵与训练

标准 `benchmarkPolicies` 为一个战斗配置运行 AI 与均匀基线，各 `runs` 局，共 2×runs。均匀基线只均匀接受现有奖励，不跳过，不主动重掷、移除或购买补给；自然角色效果仍生效，报告明确这是基线而非拥有同等决策能力的另一 AI。

`benchmarkResources` 默认仅跑 AI 的 20 组：全资源 D10；四个单项开关关闭但仍 D10 的对照；另 15 组名义配置按每关闭一类降低 2 级，组成 D8 / D6 / D4 / D2。每组使用共同公开游戏种子和策略种子配对，不能把不同难度的胜率差直接当成某一资源的纯因果效果。防御关闭是规划关闭，实际防御是否缺失另验收。相同起始种子不保证不同策略操作后每轮 RNG、奖励与编队仍相同。

报告以 `variants[].summary` 保存每组局数、胜局、Wilson 95% 区间、失败关卡、未完成局、资源统计和防御效率。每配置 1,000 局的完整 20 组为 20,000 局 AI，共用 1,000 个配对种子，不是 20,000 个不同种子；矩阵默认不额外跑均匀基线。校准种子与最终发布留出种子分开，参数/源码冻结后才能宣称正式测定。`scope=primary` 只含全资源、四个单关闭名义组和四个 D10 对照，不能当作全部组合验收。

训练可搜索输出、防御、成长、羁绊、合成、经济、期限、模拟、稀释、灵活性权重和温度。使用 `train / validation / holdout` 不同种子分区，探索可以关闭前瞻，最终留出默认使用实际部署的前瞻。候选只有在独立留出目标提高，且胜率与平均已完成关数不下降时才接受；训练分数提高不够。反复用同一留出集选择版本仍会过拟合，重要发布应另取未参与选择的种子。

## 0.4.0 当前结果与预算边界

完整 AI 平均重掷 16.307 次、移除 5.004 次、花费 225.91 信用点；生命实际消耗/生成为 64.14%，护盾抵伤/生成为 49.02%，合计 55.17%。护盾衰减作为浪费另记。

新补给规划复用已有独立反事实棋盘，预测剩余清场回合中的自然治疗、护盾、直接生命代价与逐步降低的敌方反击。需要防御且将耗尽本关购买次数时，不为短期超频收益花掉最后机会；试算立即清场或仅剩一转时仍允许输出。它没有读取隐藏 RNG，也不按失败种子设例外。预算只是有限预测，不能保证长期最优。临时丹恒的成长预测被限制在剩余登场次数内；纯全队增益与相邻/定向辅助放大分开估值。

## 页面、Worker 与离线

奖励卡推荐异步由 `src/ai-worker.js` 计算，无法启动时退回本地。页面代打调用共享决策并执行真实动作，会正常修改与保存旅程，可随时停止；说明或工具面板打开时暂缓。后台实验 Worker 另建对局，不写玩家 `game / settings / stats`；接受训练只保存新的 AI 参数，不替换当前编队或资源。

试验台可选 D1–D20、四类开关、每策略 30 / 100 / 300 / 1,000 局。标准对照采用上方配置；固定 20 组矩阵只采用上方局数，不采用上方难度与开关。页面训练每候选最多 60 局、每模型留出最多 100 局，多轮候选和验证会增加实际总局数。关闭面板后台继续，重新打开可查看或取消。

发布参考接受当前 `resource-calibration` 或 `combat-benchmark` 格式，并须满足正式发布样本、源码稳定、真实前瞻、规则与算法匹配及参数校验；本版使用完整 D10 标准对照报告，不代表资源梯度已重新验收。旧 `reward-actions-v2` / `context-v2-skip` 成绩不作为当前默认证据。参考所用参数若与已保存模型不同，页面明确标示差异，运行新实验才是当前参数的检验。

网页使用模块 Worker，单文件版使用完全内嵌的 Blob Worker，共用同一决策与引擎。离线不改概率或规则，也不调用网络 AI；存档导入验证参数范围，详见 [OFFLINE.md](OFFLINE.md)。

## 0.5.0：套路与剧情委派

套路成型人数、核心和收益来自 `archetypes.js`，AI与真实引擎共享`ids`目标过滤。同一角色的多条套路威力倍率只取最高，其他类别倍率按原规则合成；成长、反击和追击等功能可并存。击破接力允许击破者本人作为系统最强追击者，角色定向辅助默认仍找最强其他人。

`retirement-ai.js`仅用公开编队、登场次数、普通副本库存和已记录委派计数，按有限剩余转动估计供给、同场邻接与结案。它计入永久成长、当轮威力、信用点及被消耗材料的未来可用率，不能假定最后正式本体被无限消费。未抽中的角色、已培养副本、临时角色、核心保护和单待办上限均有边界。算法不读取隐藏随机数或下一张牌，估值细节与实测误差见 [委派说明](RETIREMENTS.md)。

`archetype-simulation.js`是专门的实验策略：在同一基础AI的真实奖励评分上施加公开套路偏好，并用独立策略随机流抽样；不是假装固定拿到核心或修改掉落。规划可保护已看到的缺失核心和最后成型身份，但污染清理仍交给基础AI，在生命或期限压力下优先生存、降低偏好并提前放弃薄弱备选。实验使用快速规划（`lookahead=false`）并明确记录，不能把它的胜率直接称为启用完整多棋盘前瞻的页面代打胜率。校准与正式种子、源码指纹、失败原因及未完成删失均保留。
