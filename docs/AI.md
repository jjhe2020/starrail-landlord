# 本地策略 AI 与平衡实验

AI 在浏览器本地计算，不发送游戏存档，也不需要网络服务。它是可解释的规则评估与短期随机模拟策略，目前并非大语言模型、神经网络或已经收敛的强化学习系统。

## 三选一的百分比

招募、奇物和精华的每张奖励卡都显示 AI 的**选择倾向**和理由。例如 20.37% 表示自动玩家在这一局面有 20.37% 的概率选择此卡；它不表示此卡的通关率、稀有度或中奖率。三个倾向来自当前三个候选的收益分数，通过温度控制的 softmax 转换后归一化为 1。最高分通常最常被选择，但其他候选仍保留探索概率。界面展示最多两位小数，合计可能有微小舍入差；小于 0.01% 的非零概率显示为「＜0.01%」，模拟始终使用内部未舍入的概率。

自动玩家调用与页面同一个 `recommendRewards` 函数，再将独立策略随机数交给 `sampleRecommendation`。它按累计概率区间抽样，既不偷偷只选最高分，也不使用另一套与界面不同的策略。相同规则版本、游戏状态、策略档案和策略随机种子能够重现选择序列。

页面推荐异步在 Worker 中计算，新的奖励替换旧奖励时会拒绝迟到结果；浏览器无法启动推荐 Worker 时退回本地计算。点击「AI 代打」会正常推进并保存当前玩家旅程，操作包括转动、按推荐抽奖及有收益时移除角色。可随时停止；信息浮层或工具面板打开时暂停行动，关闭后继续。批量实验与代打使用同一推荐策略，但批量实验另建独立游戏，不能把两者都描述为只读功能。

## 如何评估当前编队

评估器先用纯引擎实际选择每个奖励，得到合成后的反事实编队，然后比较边际收益，涉及以下因素：

- 每个角色的攻击方式、当前存活列分布与未来整列敌人；辅助在战斗中不会被误计为直接攻击。
- 实例的星级、已有成长、周期技能与剩余轮次；相同角色形成二星以及连续形成三星的合成机会。
- 永久编队中的不同身份、已激活羁绊、下一档阈值距离；临时角色不计入身份与合成目标。
- 相邻增益的平均命中概率、定向增益、虚无与雷属性配合、临时角色退场配合。
- 治疗与护盾来源、生命缺口、敌方威胁和已有护盾；防御足够时新增防御收益递减。
- 20 格棋盘的抽取稀释、成长角色抽取概率，以及奇物对当前编队的真实作用。
- 精华的预计积累速度、触发等待与剩余轮次；无法及时触发的精华会降低价值。
- 经典模式的产出与交租、战斗模式的输出和期限；信用点在两种模式中的用途不同。

这些是近似模型。例如相邻增益按棋盘坐标的平均邻居数估计，长期价值按有限轮次估计，不能精确预言以后出现什么奖励。丹恒和克拉拉的成长按实例累积，升星后增长速度并不按星级倍增，因此早期合成成长角色可能与后续成长存在真实取舍。

默认还比较每个候选在 4 个随机棋盘上的下一轮实际结算。模拟种子由已公开的局面确定，所有候选使用共同的一组模拟种子，以减少比较噪声。评估器明确排除游戏的 `seed`、`rngState` 和未揭示奖励，不偷看存档中预定的下一张棋盘；试验副本的随机状态在选择和转动前均替换。游戏原状态与游戏随机流保持不变。

## 自动实验与持续优化

自动实验以固定种子运行完整十二层游戏，分别报告战斗与经典模式的胜率、到达层数、转动数、失败原因等指标。它们衡量特定 AI 在当前规则下的表现，不能单独证明玩家体验已经平衡。随机选择基线用于区分策略提升与规则本身的难度。

优化器搜索可检查的策略参数：输出、防御、成长、羁绊、合成、经济、期限、模拟、稀释和选择灵活性的权重，以及 softmax 温度。训练样本与验收样本使用不同种子。快速探索可以关闭短期模拟，但最终对比会用实际部署时开启模拟的策略；报告会标明探索与验收的设置。仅训练分数提高不足以替换策略，还须通过独立验收。

目标函数优先真实通关，其次是已完成层数和本层进度，并以生命、库存及战斗回合效率区分接近的成绩。自动移除仅在编队超过 20 人、存在明确边际提升时消耗移除次数，不会在初始编队中不断剥离辅助。当前策略尚未主动决定重选或跳过，因此其成绩不等于规则的最高理论成绩。

浏览器实验在 Worker 中运行；新训练完成后，页面可使用验证通过的参数继续三选一。保存的策略档案经过严格的参数名、数值、温度和样本数校验。用户可以继续训练以寻找更好的参数，但不存在每次训练必然提高的保证，验收失败时保留原策略。重复查看同一验收集可能产生过拟合，因此重要版本仍应使用新的保留种子复测，并结合真人反馈。

试验台提供每策略 30 / 100 / 300 / 1,000 局与模式选择。双模式对照包含两个策略、两个模式，总局数为所选数量的四倍；训练每候选每模式最多 60 局，最终留出测试每模型每模式最多 100 局，实际总局数还包括多轮候选搜索与验证。每次页面实验生成新的种子。关闭工具面板会继续后台任务，重新打开可查看进度，「取消本次实验」终止任务；默认展示的是 0.2.1 已保存的 4,000 局发布评测，并非用户当前刚跑出的结果。命令行的 `npm run balance` 和 `npm run train:ai` 及报告选项见 [README](../README.md#检查与静态构建)。

0.2.0 进行了 3,200 局参数搜索与独立验收，没有发现通过验收且优于现有策略的候选，因此保留 `context-v1`。额外的 800 局发布评测使用另一组种子：战斗 AI 200/200 通关、随机策略 76/200；经典 AI 199/200、随机策略 16/200。有限样本中的 100% 不等于真实通关概率为 100%。完整设置、统计区间、规则难度判断和原始记录见 [平衡实验报告](BALANCE.md)。

0.2.1 只调整难度曲线，保留 `context-v1` 的全部权重、温度、前瞻样本数和采样精度，未削弱 AI；更高敌人生命与房租会改变公开局面，因此策略仍按新局面重新计算推荐。目标为当前 AI 每模式通关约 95%，允许 90%–98%，不是降低最高推荐选项的抽样概率来制造失败。

2,280 局难度调参与最终发布种子独立；锁定参数后完成 4,000 局发布对照，每模式各 1,000 局 AI 和 1,000 局随机选择。战斗 AI 967/1,000（96.7%）、经典 AI 946/1,000（94.6%）达到范围，随机分别为 11/1,000 与 4/1,000。这个目标针对当前基准策略，不保证玩家或后续训练模型也有相同通关率；未来策略增强后需重新测量。置信区间、失败楼层和准确复现命令见 [BALANCE.md](BALANCE.md)。

## 模块 API

`src/ai-profile.js` 提供 `DEFAULT_PROFILE`、`PROFILE_WEIGHT_KEYS` 与 `validateProfile`。权重限于 0–5，温度限于 0.25–20，反事实棋盘数限于 0–8；不接受未知权重与非有限数字。

`src/ai.js` 提供：

| API | 结果 |
| --- | --- |
| `recommendRewards(state, {profile, lookahead})` | 当前奖励的 `index / id / score / probability / reason`，以及版本、阶段与分布熵；非奖励阶段返回空列表 |
| `sampleRecommendation(recommendation, randomNumber)` | 按原始概率选择奖励索引，空列表返回 -1 |
| `createPolicyRandom(seed)` | 独立且可复现的策略随机数函数 |
| `recommendRemoval(state, {profile})` | 建议移除的角色实例 uid；没有明确提升时返回 null |
| `evaluateRun(state)` | 本项目用于比较完整游戏的数值目标，不能理解为胜率 |

## 验证

`tests/ai.test.js` 覆盖概率归一化、精确抽样边界与 30,000 次抽样的分布检查、状态不变、隐藏随机种子独立性、合成与三星连锁、不同身份羁绊、临时角色排除、模式差异、精华触发时机、移除与不可信策略数据拒绝。完整模拟、训练与 UI 的测试及实验报告由平衡实验模块补充。
