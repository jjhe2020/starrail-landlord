# v0.8.1 双版本发行验证

日期：2026-10-25。设计理由是让玩家优先理解风险、资源与当前选择，将算法、实验和制作说明保留在开发版。玩家版保留完整技能与公开条件，复杂叠加和历史结算按需展开。两版共用一套战斗规则，开发测试不覆盖玩家自动存档，存档可明确导出/导入。

## 实际结果

- `npm run check` 通过：版本一致、90张角色头像与208项源码离线资源核对成功。
- `npm test`：697项，690通过，0失败，7项默认跳过。6个浏览器入口在专项中另行执行；可选超大JSONL流式压力入口本轮未执行，不记为通过。
- `npm run build` 与 `npm run build:portable` 均通过。静态构建包含玩家/开发双入口；单文件交付为两份HTML，各自包含170个本地资源（含来源许可记录）。
- 最终两份HTML以首次离线 `file://` 在1440/320/390/820 CSS像素运行，368项UI/交互检查通过，零未捕获异常与HTTP请求。两版执行相同补给、转动、重掷、招募、移除和重载后游戏状态逐步一致，自动存档隔离、跨版导入通过；玩家不创建AI Worker，开发版真实Worker给出推荐。
- 最终开发HTML另跑完整离线回归6/6；效果解释及衣匠生命周期6 tests、169项UI检查通过。
- 最终玩家HTML的战斗动效与说明浮层20 tests全部通过。20格完整转动约2.46–2.47秒，VFX节点峰值48；另覆盖真实触屏输入模拟、动效失败后正常提交、减少动态效果、敌方反击顺序和清理。
- 最终静态 `dist` 的真实Service Worker回归10/10，包含两入口离线、开发bundle缓存、双存档、更新和缓存修复。
- 独立代码审查未发现需要阻发的问题；生产规则与0.8.0逐文件相同，哈希记录在manifest。

日志在 `validation/`，最终界面轨迹与截图在 `ui/`，源码网页检查单独在 `ui-source/`，效果专项在 `effects/`，动效指标、截图和短视频在 `motion/`。测试适配前的旧选择器失败原始日志保留，并由后续准确入口/选择器的通过记录取代；没有将失败记录计为通过。

## 平衡与平台边界

角色单卡、公开标签拿牌策略、职能乘区、永久成长与早中后期规则均没有改变。0.8.1没有重跑或完成新的平衡实验，沿用0.8.0的规则不等于证明其平衡；既有终局压力集中问题仍待后续调查。旧95%与D10资源映射仅属于历史方案，本版不将其作为发布门槛。多维玩家偏好与难度矩阵尚未实施，下一阶段先建立测试设计与基线，再提出调优。
