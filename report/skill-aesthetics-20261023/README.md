# 全角色技能设计评审

这是一份未应用的设计与表达评审，不是游戏更新。第四轮已将90人的默认攻击方式、默认攻击倍率与基础攻击力独立放到卡面，技能正文只描述特殊效果；保留统一追加攻击、三个增幅区、治疗/护盾公式及10项奇物评审。46名原辅助逐角色给出默认倍率起测建议与理由，20%、25%不是范围或固定档位。技能原文保留0.7.0快照，与当前0.7.1的角色定义逐字一致。

推荐双击本目录的 `打开评审.command`，自动启动本机服务并打开 `http://127.0.0.1:5178/#reviews`。终端窗口需保持开启；服务已经运行时会复用。此入口只提供评审HTML，不开放整个项目目录。也可执行 `node report/skill-aesthetics-20261023/preview.mjs` 启动，或用 Safari/Chrome 直接打开 `index.html`。Codex内的本地文件入口可能受协议限制，不宜作为唯一入口。

报告本身无网络依赖，支持全文搜索、职能/建议/剧情结论组合筛选、语义分歧、个体重点重构与追加攻击相关筛选、排序，以及导出当前筛选结果为UTF-8 CSV。另有可调试算器，比较攻击力、造成伤害和敌方受到伤害三种独立效果对攻击、治疗与护盾的影响。参考链接需要联网才能访问，阅读评审不需要。

完整文字表格在 `角色技能点评-v0.7.0-20261023.md`，当前CSV为 `星穹转轮-卡面属性与技能-90角色.csv`（90行、16列），奇物表为 `仪器改造建议.csv`；第二、三轮CSV保留作历史。`current-skills.json` 保留完整角色原始快照；三个 `review-*.json` 保留首轮美学评审；两个 `lore-*.json` 为逐角色剧情复核；`terminology-model.json` 是严格机制解释与未采纳模型；`review-data.json` 为汇总数据。`source-manifest.json` 的摘要对应锁定提交，不声称整个工作区仍是0.7.0。

`user-directions.json` 记录用户原意与尚未决定的细节；`terminology-per-character.json` 给出90条新方向草案；`relationship-audit.json` 另审10组现有委派。上一轮“导师只提升攻击角色威力”的基线已被本轮全角色攻击力模型替代；旧提案折叠保留作历史。衣匠的2次期限沿用旧参数作对照，不把用户举的3次当固定要求。

评分是讨论设计美学与表达清晰的主观量尺，不是强度、胜率或平衡证明。7项文案/实现语义分歧需先确认原意，不能作为无争议文案直接替换。机制候选全部未采纳，后续仍须按项目要求分别验证。

生成与完整性核验：

```sh
node report/skill-aesthetics-20261023/build-report.mjs
node report/skill-aesthetics-20261023/verify-report.mjs
node report/skill-aesthetics-20261023/verify-combat.mjs
```

卡面属性数据见 `card-attributes.json`；第四轮技能正文通过生成器从旧草案分离，独立字段为 `skillCopy`。升星基础值、本局永久提升和本次增益分别记录；各角色星级表尚待设计。其余战斗数据分别见 `combat-model.json`、`combat-per-character.json`、`combat-equipment.json`；检查材料见 `integrity-verification.json` 与 `combat-verification.json`。`verification.json` 和旧截图记录首轮验证，不作为补充版布局证据。补充版访问当前file:页面时被浏览器安全策略阻止，未绕过限制；第四轮继续以静态结构、脚本执行、数据、CSV及试算公式检查为证据，没有重新完成桌面/窄屏可视验收。浏览器可视检查不作为通过项。

`index-first-review.html` 和原 `星穹转轮-技能评审-v0.7.0-90角色.csv` 保留首轮对照；本轮新草案以 `index.html` 为准。游戏源码、版本、标签、Release与站点均未由本报告修改。

HoYoWiki词汇参考位于奇物表之后；它提供术语及效果表达线索，不作为本作公式的官方认证。理论来源与本文借用范围完整列在报告页末尾，剧情引用在每名角色下可展开查看。部分资料通过官方域名搜索索引或游戏文本转载核对，未声称全部原页直读或逐句审校最新主线；未直核的视频上传账号按第三方资料标注。逐角色点评属于本次评审判断，不代表引用作者对本项目的评价。
